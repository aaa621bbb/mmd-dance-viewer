## 0. 一句话结论

**不加一个大功能，只加一个模式。** 现有工程里已经有这个游戏 70% 的地基——**第一人称控制器、虚拟摇杆、射线碰撞、模型加载、VMD 播放、布料物理、阴影、文件桥**全都在，缺的只有三样：**一座城、一个"会踩你"的她、一层反馈**。

本方案只做这三样，并且**不碰**现有舞蹈预览的任何既有行为。

## 1. 现状盘点（已核实，可复用清单）

### 1.1 已经有的、直接拿来用

| 能力 | 代码位置 | 说明 |
|---|---|---|
| 引擎/场景/唯一渲染循环 | `frontend/src/main.js` `main()`；`window.__mmd.renderFrame` | ⚠️ 铁律：全项目只能有这一个 `runRenderLoop` 引用（不同箭头函数引用会导致多循环叠加 → 双倍负载） |
| 模型加载 | `loadAndPlay()` → `LoadAssetContainerAsync(url, scene)` + `mmdRuntime.createMmdModel(mesh, {...})` | 支持多模型 `modelList`，模型来自设备文件夹（SAF） |
| VMD 动作播放 | `loadMotionTrack()`、`MmdCompositeRuntimeModelAnimation` | 动作/表情/相机三轨 |
| 布料物理 | babylon-mmd WASM(SPR)；`__mmd.setFabric/setPhysics`（重力/子步/平滑） | 这是"存在感"的一半，游戏模式**保持开启** |
| **第一人称控制器** | `expUpdate(dt)`：摇杆输入 → yaw/pitch → 位移 | 已有独立 `UniversalCamera`、防自转根治、单例 observer + `expActive` 守卫 |
| 地面/碰撞射线 | `expGroundY()`、`expCollideDist()` | `scene.pickWithRay` + predicate 过滤 |
| 全屏触控 UI | `index.html` `#exploreUI`（`#expJoystick` 摇杆 + `#expLookZone` 视角区 + 退出/速度/灵敏度） | **直接复制成 `#gameUI`**，改皮 |
| 阴影 | `_applyShadowRenderList()`、`dirLight` 阴影 | "巨人巨大阴影压在街上" = 巨人感的核心来源，已经在用 |
| 后处理 | SSAO2 / Bloom / ACES；`_suspendPostProcess()`（切相机必须挂起，否则卡死） | 游戏模式默认关闭 SSAO（手机太贵） |
| 文件桥 | `MmdFileBridge` + `http://mmdext/<相对路径>` 虚拟域 + CORS 头 | 玩家从文件夹里挑模型/动作 = **巨人由谁扮演由玩家决定** |
| 视频导出 | MediaCodec（`MmdExportBridge`） | 可用来"录一段踩城"（P2，不改） |

### 1.2 现有探索模式的三个数值**不能沿用**

```
expEyeH     = 0.05   // 眼高
expWalkSpeed= 0.03   // 行走速度
```
这是"把小人与 20 单位高的模型对比"留下的历史值（约 1:400 比例）。**游戏模式必须用第 3 节的尺度系统自行推导，禁止直接继承这两个数，也禁止在游戏逻辑里出现裸数值。**

## 2. 接入设计

### 2.1 入口

- 顶部工具条（`index.html` `#topBar`）在「探索」旁新增一个按钮：**`🎮 玩法`**（`#gameBtn`）。
- 点击 → `window.__mmd.enterCityMode()`；游戏内左上角红色按钮 `#gmExitBt` → `window.__mmd.exitCityMode()`。
- 进入时**不重载模型**：把当前选中模型（`window.__mmd.mmdModel`）直接当作**她**。
  > 体验上这是一句很漂亮的话：*载入你想看的模型 → 点「玩法」→ 她就是你脚下那座城上的巨人。*
- 若当前没有模型：按钮提示"先选一个模型"，不进入。

### 2.2 生命周期（进出必须零残留——本仓库被这事坑过）

```
enterCityMode():
  1. 记录并保存：主相机状态 / activeCamera / ground.enabled / 现有 render 列表 / 当前动画状态
  2. 挂起 postProcess（复用 _suspendPostProcess）
  3. 隐藏舞蹈地面(ground 40×40)与不需要的街具层，隐藏 UI（复用 expHideEls 思路）
  4. 建城（首次生成后缓存，二次进入不重建）
  5. 玩家出生点 = 她脚边 8~15 m 处（按 K 换算），相机切到玩家相机
  6. 注册**单例** game observer（`onBeforeRenderObservable`），内部首行守卫 `if (!cityActive) return;`
  7. 她的动画：切到"城市行为状态机"接管

exitCityMode():
  1. cityActive = false（observer 立即空转）
  2. removeObserver（失败无害）
  3. 还原子步骤 1 的全部记录 + 恢复 postProcess + 主 UI
  4. 她的动画状态交还舞蹈播放器（继续播原来的动作）
```

**硬指标：连续进出 10 次，帧率不降、画面不变暗、无 observer 累积。** 验收方式：HUD 角标打印 `scene.onBeforeRenderObservable.observers.length`，进出 10 次后仍为固定值。

### 2.3 新增文件（全部新文件，不改老逻辑）

```
frontend/src/game/
  index.js       // 模式路由：enterCityMode/exitCityMode, 生命周期, 单一 game observer
  scale.js       // 【唯一尺度来源】K 与所有米制换算
  city.js        // 城市生成器（分区/街区/楼/路面/街具/车）
  player.js      // 玩家控制器（基于 expUpdate 改造 + 城市碰撞集）
  giant.js       // 她的行为状态机 + 脚部接地/根位移
  stomp.js       // 踩踏判定（足底圆 + 落地时间窗）
  fx.js          // 反馈：脚影贴片/震屏/灰尘/慢动作
  hud.js         // HUD：计分/播报/心跳/提示
  config.js      // 所有可调数值（米制！），集中一处，真机调参只改这里
```

`frontend/src/main.js` 只允许加**两处**改动：
1. `import { installCityMode } from "./game/index.js";` + `installCityMode(window.__mmd);`（在 `main()` 末尾）
2. `window.__mmd.enterCityMode / exitCityMode / isCityActive` 三个导出（由 `game/index.js` 注入，main.js 里只留一行注释）

## 3. 尺度系统（本方案的头号天条）

### 3.1 两条要遵守的事实

**事实 A（已由代码佐证，阶段 0 用打印包围盒实测确认）**
babylon-mmd **不做米制换算**，PMX 顶点按 MMD 原生单位进入 Babylon → **标准 PMX 模型约 20 单位高**。
佐证：本仓库主相机 `ArcRotateCamera(radius=25, target=(0,10,0), lower/upperRadiusLimit=8/60)`——只有模型≈20 单位高时这套参数才成立。

**事实 B（死规矩）**
**她的 `scaling` 永远 = 1。**
PMX 的布料刚体、弹簧、IK、VMD 位移全是原生尺度标定过的；一旦缩放，弹簧脱离标定区间 → 裙子头发乱飞。
> 这条在 Unity 版方案里同样成立（那边是 `worldScale≈0.05` 缩世界）。**两边口径一致：缩世界，不缩模型。**

### 3.2 唯一常量 K

```js
// scale.js
// K = 多少个 babylon 单位 = 1 米
let K;                       // 运行时算出
let G_target = 50;           // 【可调】她的真实身高（米）——默认 50m，20 层楼高

export function initScale(mmdModel, opts) {
  const H = measureModelHeight(mmdModel);   // 运行时量：包围盒高度，取 5%~95% 分位去头发/裙摆毛刺
  K = H / G_target;                          // 标准模型: 20/50 = 0.4 (1 单位 = 2.5 m)
  return K;
}
export const u = (meters) => meters * K;     // 米 → 单位（全项目唯一换算入口）
```

**所有设计数据一律写"米"，代码里过 `u()`。禁止裸数字。**

### 3.3 换算表（K = 0.4 时，供校对用）

| 项 | 真实（米） | 单位 | 备注 |
|---|---|---|---|
| 她 | 50 | 20 | 模型原生高度，scaling=1 |
| 玩家身高 | 1.6 | 0.64 | 她 = 你的 31 倍 |
| 玩家眼高 | 1.5 | 0.60 | `expEyeH` 在城市模式里由这里推导 |
| 行走 / 跑 | 3 / 6 | 1.2 / 2.4 | 穿过 7m 宽马路 ≈ 2.3 秒 |
| 车道宽 | 7 | 2.8 | 双向两车道 |
| 人行道高差 | 0.15 | 0.06 | 上街沿要能踏上去 |
| 街区块 | 60×60 | 24×24 | |
| 楼高 | 12~40 | 4.8~16 | 她比大部分楼高 |
| 路灯 | 8 | 3.2 | |
| 汽车 | 4.5×1.8×1.5 | 1.8×0.72×0.6 | |
| 脚掌半径（判定） | 0.75 | 0.3 | 她脚长 ≈ 7.5 m |

**相机**：`minZ = u(0.05)`、`maxZ = u(400)`（≈160 单位，够看全城）、`fov = 0.9`。
**阴影参数**：`shadowMinZ/shadowMaxZ`、bias 必须按单位重标（照搬舞蹈场景的数值会全黑或漏光）。

## 4. 城市生成器（city.js）

### 4.1 结构

```
格网 = 3×3 街区块（P0）→ 总占地约 200×200 m ≈ 80×80 单位
每块地 = 一栋楼（退台 2~3 段）+ 屋顶道具（水箱/广告牌）
街 = 车行道 7m + 两侧人行道 2.5m（抬高 0.15m）+ 人行横道
街具 = 路灯 / 消防栓 / 报刊亭 / 自动售货机 / 行道树 / 停着的车
```

### 4.2 三条性能铁律

1. **窗格用 1 张程序化贴图**：`DynamicTexture` 生成一次（随机点亮的窗格），全城共用 **1 个材质**，按 UV 平铺。**不要每栋楼一个材质**（700 个材质 = 700 次绘制调用 = 手机必炸）。
2. **能合批就合批**：同材质楼体用 `Mesh.MergeMeshes(..., true, true)`；街具/树/车用 **thin instances**；目标 **整城 draw call < 30**，三角形 < 8 万。
3. **城市只接收阴影、不投射**（`receiveShadows = true; castShadow = false`）——省一半 shadow map 成本；阴影是给她用的。

### 4.3 与她的物理的关系（重要）

她的布料物理只有一条 **无限地面平面**（babylon-mmd 内置 ground collision）。**楼不参与她的物理**，所以楼一定会被她穿模。

**对策（不是妥协，是设计）**：
> **楼被踩到 → 触发式"压扁"**（Y 轴缩到 5%，200ms 补间）→ 消失。同街区邻近楼 100~400ms 内依次压扁（连锁）。
> 穿模被"压扁动画"盖过去，玩家看到的是"楼被踩平了"，还额外收获爽点。**这是本方案里最划算的一笔。**

建筑的"可踩"判定不给每个 mesh 挂碰撞，而是**街区块级**：她落脚点落在哪个街区 → 该街区所有楼压扁（一次遍历，零物理成本）。

## 5. 玩家控制器（player.js）

复用 `expUpdate` 的整套数学（yaw/pitch/手性/防自转），**只改四处**：

1. **数值来源**：`eyeH = u(1.5)`、`walk = u(3)`、`run = u(6)`（`expInput` 里加 run 标志）。
2. **碰撞集收窄**：不要再对所有 `renderingGroupId===0` 的 mesh 做 `pickWithRay`（城市 700+ mesh 会拖死）。改成：
   ```js
   const cityPickables = [...];   // 城市楼体/街具/巨人以外的地面
   hit = scene.pickWithRay(ray, m => m.__isCity === true || m === ground);
   ```
3. **上下沿台阶**：`expGroundY` 命中台阶时允许 `+u(0.2)` 的自动跨步（否则 0.06 单位的路缘会卡住玩家）。
4. **禁止用射线打巨人**：她的 mesh 是 3 万+ 三角面，射线太贵，且踩踏判定本来就是**解析式**的（第 6 节）。玩家的"碰到她"用她的骨骼胶囊/圆柱近似。

**玩家能力（P0 只有两条，别加）**：走/跑、蹲（降低 30% 视高、不被视线锥看见）。
> ⚠️ 道具/消耗品（烟雾弹、护盾、加速饮料、诱饵、投掷物）**不做**——已被明确否决。

## 6. 她：行为、走路、踩踏判定

### 6.1 行为状态机（giant.js）

```
idle      ← 待机：慢放当前 VMD（0.4 倍速），偶尔转头
approach  ← 朝玩家所在方向平移（速度 = strideSpeed 常量）
stomp     ← 落脚（从 approach 进入，检测到脚落地即触发 stomp 事件）
scan      ← 搜索：转头扫视（P1，配视线锥）
```

**P0 的巧劲**：她的动作**就用玩家自己从文件夹里选的 VMD**。
- 有走路 VMD → `approach` 播走路；
- 只有舞蹈 VMD → 也照样跑（`approach` 里播舞蹈，只做平移 + 踩踏判定照常生效）；
- 状态切换用 `MmdCompositeRuntimeAnimation` 的 span 交叉淡化（已有能力）。

结果：**不需要任何新动画资源，游戏就能跑起来。**

### 6.2 走路不飘（P0 粗暴版 / P1 精修版）

- **P0**：给每个动作手调一个 `strideSpeed`（单位/秒）存进 `config.js`——看着对就存下来。跑偏了就是调一个数。
- **P1（正确做法）**：读双脚骨骼世界 Y，取"支撑相"的那只脚，用其 `-ΔZ` 反向补偿根节点位移 → 真·脚踩地不滑。

### 6.3 踩踏判定（stomp.js，全项目最核心的 30 行）

```js
// 每帧：取双脚骨骼世界坐标（阶段0 先打印骨骼名表确认）
const footL = worldPos(bone("leftFoot")), footR = worldPos(bone("rightFoot"));
// 着陆事件：Y 由高到低穿过阈值 且 下降速度 > 阈值
if (prev.y > landY && now.y <= landY && (prev.y - now.y) > u(0.5)) {
    const c = { x: now.x, z: now.z };               // 落脚圆心（地面投影）
    const R = u(0.75);                               // 脚掌半径
    const d = distance2D(player.pos, c);
    if (d < R * 0.6)      → 直击（结束）
    else if (d < R)      → 命中（扣血/减速）
    else if (d < R * 2)  → 擦身而过（加分 + 播报）
    onStomp(c, R);      // 触发：震屏 + 灰尘 + 街区压扁 + 脚影
}
```

> ⚠️ **骨骼名待确认**：babylon-mmd 会把日文骨名映射成英文标准名。阶段 0 第一件事就是 `console.log(mmdModel.skeleton.bones.map(b => b.name))`，确认 `leftFoot/rightFoot`（或 `左足首/右足首`）到底叫什么，再写死到 `config.js`。

### 6.4 她的物理

**保持开启**（布料/头发/裙摆 = 存在感的一半）。**不动物理参数、不动 scaling。**
唯一例外：如果真机帧率不够，允许把 `substeps` 降到 2（`__mmd.setPhysics({substeps})` 已存在）。

## 7. 反馈层（fx.js / hud.js）——按性价比排序，P0 只做前五

| 优先级 | 反馈 | 做法 | 成本 |
|---|---|---|---|
| **1** | **脚影先行贴片** | 一个贴地圆片，随她的脚下降而放大、变深；踩下瞬间闪一下 | 极低，效果最大 |
| **2** | **播报** | HUD 一行字：`她看到了你` / `擦身而过 +50` / `你被踩扁了` | 极低，性价比第一 |
| **3** | **震屏** | 命中/她落地时 camera ±0.3 单位抖动 0.2s（复用相机的 position 写入处） | 低 |
| **4** | **灰尘** | 落脚点一圈 8~12 个薄片粒子（`ParticleSystem` 或 12 个薄片 mesh 环形散开 0.6s） | 低 |
| **5** | **心跳** | 她离你 < 2R 时，HUD 心跳图标 + 音效加速（音效可后补） | 低 |
| 6 | 慢动作特写 | 落脚前 0.3s 把动画 timeline 推进倍率降到 0.25（本项目 timeline 已是"绝对时间×倍率"结构，改倍率极便宜） | 中 |
| 7 | 街区连锁塌 | 第 4.3 节 | 中 |
| 8 | 视线锥潜行 | 她的朝向前方锥形 + 你的视觉提示（P1） | 中 |
| 9 | 换鞋（高跟/长靴/运动鞋/赤脚 = 换玩法） | 换 PMX 模型 = 已天然支持 | 低（P2） |
| 10 | 她的日常（坐着/看手机/打哈欠） | 需要**新 VMD**（我无法制作 VMD，需外部资源） | 高（P2） |

**计分**：只做最朴素的一条——**活着的时间 + 擦身而过奖励**。不做技能树、不做数值成长、不做每日任务、不做联机。

## 8. Android / 构建纪律（**必读，否则改了没效果**）

1. **CI 只跑 gradle，不构建前端**。`app/src/main/assets/dist/main.js` 是**已提交的构建产物**。
   → 改完前端**必须**：
   ```bash
   cd frontend && node build.mjs && node deploy-to-apk.mjs
   ```
   然后**把 `app/src/main/assets/dist/main.js` 一起提交**。只改 `src/main.js` 不重新打包 → APK 里跑的还是旧代码。
2. 前端依赖已装（`npm install`），沙箱内 `node build.mjs` 实测通过（产物 ≈15.9 MB，未压缩，与仓库现有产物一致）。
3. 目标帧率 **60 FPS**（`__mmd.engine`）。超预算时的**取舍顺序**（从先砍到后砍）：
   灰尘粒子 → SSAO（本来就关）→ 城市窗格贴图分辨率 → 街区数 3×3 → 2×2 → 她的物理 substeps 3 → 2。
   **最后才动**：她的布料物理（关掉她就不"活"了）。
4. 横屏：游戏模式强制横屏（`AndroidUI` 已有切横竖屏能力），竖屏体验不做。

## 9. 分阶段实施（每阶段都有"能验证的产出"）

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| **尺度搞错**（最致命） | 阶段 0 强制：打印 H/K + 方块并排视觉确认；所有数值过 `u()` |
