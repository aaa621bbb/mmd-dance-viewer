## 1. 视角只能左右，不能上下 🔴 P0

**根因（`frontend/src/game/player.js:205-212`）**

```js
if (giantFeet && giantPos) {
  const dist = Math.hypot(pos.x - giantPos.x, pos.z - giantPos.z);
  if (dist < u(400)) {                                  // u(400) = 21.7 单位
    const targetPitch = -0.15;
    pitch = pitch * 0.95 + targetPitch * 0.05;           // ← 每帧把俯仰拉回去
  }
}
```

巨人全知追踪、永远在你附近（实测 7 单位），条件恒成立 → 每帧砍 5% 并拽回 -0.15 rad，松手 0.6s 内必然回正。

**改法**：删掉这段。想保留"她盯着你"的演出，就改成相机叠加量 `camera.rotation.x = pitch + lookAtOffset`，且**玩家 2s 内有过输入时偏移归零**。永远不要写回 `pitch`。

**验收**：垂直拖 0.5s 松手，1s 后 pitch 保持 >0.3 rad；静止 5s 不回落。

## 2. 灵敏度太低、滑杆太复杂 → 全盘照抄探索模式 🔴 P0

**根因**：`hud.js` 把触控增量归一化成 `dx/100` 限 ±1，`player.js` 再乘 `SENS × MAX_RATE(240°/s)`，而且**输入每帧被消费一次**（`player.js:201-204` 每帧末尾清 `lookNorm/hasLook`）→ 跟手差、速率随事件密度变化、量级比探索模式慢 5~10 倍。还暴露了 4 个滑杆（sensH/sensV/maxRate/inertia），用户看不懂。

**改法：照抄探索模式（`main.js:1210-1228` 是 golden）**

```js
var ddx = expInput.lookDX * 0.006 * expSens;   // 逐帧像素增量 → 弧度
yaw   += clamp(ddx, -0.03*expSens, 0.03*expSens);
var ddy = expInput.lookDY * 0.004 * expSens;
pitch += clamp(ddy, -0.03*expSens, 0.03*expSens);
cam.rotation.y = yaw; cam.rotation.x = pitch;
```

1. `player.js` 删掉速率/惯性/限幅那套，改成上面的**逐帧增量累加**；`hud.js` **不要**除 100、**不要**限幅、**不要**每帧清零（累计到下一帧消费一次）。
2. UI 只留：**视角灵敏度 0.2~4.0（默认 1.0）** + **上下反转开关**。删掉另外三个滑杆，localStorage 改 `game_look={sens,invertY}`。
3. 鼠标/WASD 直接复用探索模式（`movementX/Y`、`expWalkSpeed`），摇杆保留，只当作"代替 WASD"。
4. 保留"摇杆与视角区 identifier 互斥"（这部分是对的）。

**验收**：同一手势在探索/游戏里转过的角度差 ≤10%；一个滑杆 0.2→4 转速单调变化 20 倍。

## 3. "房子不接地、大片留白、不够精致" 🔴 P0

**实测（`CITY_SEED=20260912`）**

| 指标 | 实测 | v4.0 规范 |
|---|---|---|
| 街区边长 | 66 PH = **3.584 单位** | — |
| 单栋建筑最大边（中位） | **0.510 单位 = 9.4 PH** | 应占满所在街边（≥40 PH） |
| 建筑高度（中位） | **0.239 单位 = 4 PH**（最高 120 PH 只有地标塔） | 4~12 层 ×12 PH = 50~150 PH |
| 建筑投影 / 城市面积 | **4.6%** | — |
| 街区填充率（中位） | **7.8%** | 商业 ≥60%、住宅 ≥45% |
| 空地占城市 | 72%（城内 56%） | ≤15% |
| 最大连通空地 | **84.6 单位见方**（≈1558 PH） | — |

结论：**"城市"是在 3.6 单位见方的大街区里摆了一堆 0.5 单位宽、4 PH 高的小盒子** → 这就是"大片留白 + 楼房差"。

另外两条具体来源：

- **地面纹理被拉伸**：`city.js:641` 每个 tile 的地面只用一张 25×25 单位的 quad、`uvScale=1`（把 atlas 里 248px 的沥青格摊在 25 单位上）→ 视觉上就是一块纯色，看着"糊/悬空"。
- **地面只存在于城市方框内**（±50.2 单位），之外直接是虚空与雾（首帧截图下半画面整片糊色即此）。
- 门框/雨棚/招牌**凸出楼体 AABB 最多 0.033 单位（0.6 PH）**（射线审计抓到的）。

**改法**

1. 街区边长 66 PH 保留；街区四边按**沿街连续立面**生成：每边 2~4 栋、**合计占 ≥80% 边长**，进深 15~25 PH，转角封口（相邻楼缝隙 ≤2 PH）。
2. 层数：基座 8~14 PH + 标准层 ×N（每层 12 PH）+ 顶部收分/女儿墙；住宅 4~8 层、商业 6~14 层。
3. 街区内部补 1~3 栋内院楼/低矮配楼，把**填充率拉到 ≥60%（商业）/≥45%（住宅）**。
4. 地面：tile 沥青 quad 改 `uvScale=24`（每格≈1 PH）；人行道/草地同步；2048 档把路面格提到 512×512。
5. 城市外圈加 400×400 单位大地面，消灭"城市边缘虚空"。
6. 装饰凸出要么并入楼体 AABB，要么**内缩 0.01 单位**进墙面。
7. `audit-city.mjs` 改成**硬门槛**（不再是自证）：每街区填充率表（低于阈值 exit 1）、每栋段数 ≥3、相邻楼缝隙 ≤2 PH、装饰凸出 >0.01 单位报错。

**验收**：审计表里每个商业街区 ≥60%；随机 20 栋截图，门/窗/基座/屋顶设备齐全。

## 4. "天空没有做" 🟠 P1

**根因（`city.js: setupSkyAndLights`）**

- 天空是**直径 200 的球 + `infiniteDistance=true`，但不是相机子节点**，位置固定在原点 → 走远就穿出球体。
- 渐变是 16×512 竖直图，贴到球面 **V 轴方向未校验，很可能上下颠倒**（天顶是地平线橙色）——与首帧截图顶部一片橙黄吻合。
- 雾 `EXP2 density=0.025`、雾色 `(0.79,0.64,0.48)` 偏亮橙 → 76 单位外全糊成橙，观感就是"远处留白"。
- 远景剪影环 `SKYLINE_R=70` 只有 1 个单色 mesh。

**改法**：天空球每帧跟随相机；显式对齐 V 轴（天顶深蓝 `#1b2a4a`、地平暖橙 `#e0a878`）；雾色改天顶暗版 `(0.20,0.24,0.33)`、`density` 降到 0.008~0.012 并加高度雾；远景加两层深浅剪影 + 太阳 + 2~3 条云带。

**验收**：抬头截图，天顶像素偏蓝、地平偏橙，无接缝；低头看地，地面纹理可辨（不是纯色）。

## 5. 巨人动作：只动了腿、上半身是雕像、朝向反的 🔴 P0（本次最大问题）

### 5.1 证据一：上半身几乎没有幅度（解析真实 VMD 得到）

| 动作 | 骨 | 整段旋转总幅度 | 判读 |
|---|---|---|---|
| `walk.vmd` | 左腕 / 右腕 | **18°**（±9°） | 走路不摆手，等于没做 |
| `walk.vmd` | 上半身 | **5°** | 没有躯干扭转 |
| `walk.vmd` | 首 / 頭 | 3° / 1.5° | 头是死的 |
| `walk.vmd` | 左足ＩＫ / 右足ＩＫ | 位移 8.6 / 7.3 单位 | **只有腿在动** |
| `idle.vmd` | 上半身 | **0.49°** | 雕像 |
| `idle.vmd` | 首 | 2.38° | 雕像 |
| `idle.vmd` | 左腕 / 右腕 | 2.95° | 雕像 |
| `idle.vmd` | センター | 位移 0.059 单位（≈1 PH） | 只有极慢呼吸 |

（注：`giant.js` 里代码叠加的"低头"确实在动——实测 HUD 显示 `head 22°`——但那是代码加的姿态，**跟动作文件无关**，而且只有低头，没有摆臂、没有躯干、没有重心。）

### 5.2 证据二：朝向反了（骨骼实测）

在游戏里读她模型的骨骼世界坐标：

```
左目 / 右目 : ( ±0.314, 18.565, -0.4685 )   ← 眼睛在头部局部 z = -0.47
頭          : ( 0, 17.886, -0.0055 )
左足首/右足首: ( ±0.8746, 1.481, 0.400 )
```

→ **模型的脸朝局部 −Z**（眼睛在 −Z 侧），左足在 +X。而代码里：

```js
const desiredYaw = Math.atan2(toPlayer.x, toPlayer.z);   // giant.js:274
```

`yaw = atan2(dx,dz)` 会让**局部 +Z** 指向玩家 → 她永远把**后脑勺**对着你。这就是"背向我走路"。

**改法**：`desiredYaw = Math.atan2(-toPlayer.x, -toPlayer.z)`（等价于 +π）。同一处还要把转向速率在追赶时提到 45°/s，并加"目标朝向平滑"（不要每帧硬插值到目标角）。

**验收（无头可测）**：跑 300 帧后，取 `头骨世界坐标 → 眼骨中点` 的水平向量 `f`，与 `玩家 − 她` 的水平向量 `t` 求夹角，**必须 < 25°**（现在恒 ≈180°）。

### 5.3 证据三：切换动作时没有交叉淡化（腿"瞬移"的主因）

`frontend/src/game/motions.js`：

```js
// 淡化：若有旧 handle，尝试过渡（简化：直接替换，0.4s 内由外部控制 timeScale）
if (currentHandle) { try { currentHandle.dispose(); } catch(e){} }
mmdModel.setRuntimeAnimation(handle);
```

注释自己写了"简化：直接替换"。所以 `approach → stompNear → stomp → recover` 每次跳变都是**硬切姿势**：腿从上一动作末帧直接跳到下一动作首帧——就是你看到的"腿从一个地方突然到了另一个地方"。而且 `setMotion` 每次调用都 `await import(...)` + `new MmdCompositeAnimation()`，还是异步竞态。

**改法**：三个动作常驻 `MmdCompositeAnimation`（各一个 span），切换只改**权重**（0.3~0.4s，smoothstep），**永不 dispose / 永不重建**；切 stomp 时把它的 `frameTime` 归零。

**验收**：录制 30s 脚骨逐帧曲线，**单帧最大位移 < 0.25 单位**，状态切换前后 3 帧内 < 0.3 单位。

### 5.4 证据四：关键帧太稀 + 速度不连续

| 文件 | 骨 | 关键帧间隔 | 相邻关键帧最大位移 | 其余段 | 位置 |
|---|---|---|---|---|---|
| `walk.vmd` | 左足ＩＫ | 每 5 帧 | **1.97 单位（36 PH）** | 0.3~0.5 单位 | f60（循环末段） |
| `walk.vmd` | 右足ＩＫ | 每 5 帧 | 1.97 单位 | 0.3~0.5 | f30 |
| `stomp.vmd` | 右足ＩＫ | 每 3 帧 | 1.20 单位（**纯线性斜坡**，无缓动） | — | f51 |
| `stomp.vmd` | センター | 每 3 帧 | 0.63 单位（**纯线性横移**） | — | f75 |

首尾闭合本身是好的（所有骨首尾位移差 = 0.0000），问题是**速度不连续**（末段是常规段的 4~6 倍）。另外 `walk` 的骨盆左右摆周期是**整周期**（f0→f30→f60），而正常步态是**每半步一次**；垂直起伏也是一周期一次，应为两次。

**改法（`tools/gen-motion.mjs` 重写）**

1. 所有曲线用**正弦/贝塞尔**生成，禁线性斜坡。
2. 关键帧密度：**每 2 帧**（walk 60 帧 → 每骨 ≥30 键）。
3. 步态绑定：步幅 22 PH、周期 60 帧 → 位移速度 = 22 PH/s（改速度必须同步改周期，**脚不许滑步**）。
4. 骨盆左右摆周期 = 半步（30 帧）、垂直起伏周期 = 半步、相位差 90°。
5. 脚掌接地判定用**相对地面高度**（现在用绝对世界 Y，实测脚骨 Y 在 1.36~7.48 之间飘，阈值形同虚设）。

## 6. "巨人不会追着我踩，一直在原地循环" 🔴 P0

**根因（`giant.js:229-272`）**

```js
case "approach":
  if (distPH < 200) { state = "stompNear"; ... }   // 200 PH = 10.9 单位
  break;                                          // ← approach 里根本没有"移动"代码
```

玩家站在她脚边时距离约 7 单位 = **129 PH < 200** → 一进 approach 立刻判"已就位"→ stompNear → stomp → recover → approach → 又立刻回 stompNear → **无限原地踩**。唯一的位移来自"支撑脚接地驱动根位移"，实测 8 秒只走了 0.41 单位。

**遥测（7.7s / 46 样本）**

```
state 分布: {stomp: 29, recover: 7, stompNear: 10}   ← 一次 approach 都没进
巨人 root: (-0.001, 21.289) → (-0.003, 21.696)   总位移 0.407 单位
玩家-巨人距离: 7.07 ~ 7.48 单位（不收敛）
```

**改法**

1. `approach` 显式位移：`root.position += normalize(player-root) * u(22) * dt`（22 PH/s，与 walk 步幅/周期绑定）；朝向用 5.2 的公式，转向 45°/s。
2. 进入 `stompNear` 的条件改为 **`distPH < 30`（≈1.6 单位，她脚掌椭圆量级）**，否则一直走。
3. 接地判定改相对地面高度；`canDrive` 不要依赖 `currentMotion`（现在 motion 没切成功就永远不驱动）。
4. 卡住自救：连续 3s 位移 < 5 PH → 清掉前方 2 单位内的楼（复用 `stomp.js` 的 `removeBoxesInRadius`）。
5. `recover` 之后**真的走**，只有走进 30 PH 才踩；踩完留 0.5s 站定（这就是逃跑窗口）。

**验收（新增 `tools/audit-giant.mjs`，无头 1800 帧）**：玩家放 900 PH 外 → 距离单调下降（允许 5% 抖动）、30s 内 `finalDist < 40 PH`、期间 `approach` 位移 > 400 PH、朝向夹角 <25°。

## 7. "楼房做得跟屎一样" 🔴 P0

**实测**：全城 1610 栋、4003 个 build AABB（一栋拆 2~3 段），只有 4 种窗格格位；门/雨棚是 L1 才有、阳台 L2、屋顶设备 L3 —— 也就是**手机默认档看到的是"小盒子 + 一个窗户纹理"，屋顶全空**。

**改法（按优先级）**

1. 先按 §3 解决**体量**（占满街边、连续立面、4~12 层）。体量对了，"差"的感觉少一半。
2. 每栋 ≥3 段：基座（8~14 PH，必须有门 + 橱窗 + 雨棚 + 招牌）→ 标准层（12 PH/层，窗格 + 腰线）→ 顶部（女儿墙 + 屋顶设备：水箱圆柱/通风箱/电梯机房；L2 起天线）。
3. 贴附物（门/窗/雨棚/空调/晾衣杆/防盗窗/落水管/涂鸦/海报）**共用楼体 yaw 与底面**，凸出 ≤0.01 单位。
4. 同一街区不许出现两栋相同窗格+色调；用"分区色 + 三档高度 + 两种收分"做层次。
5. **屋顶不许空**：L1 起每栋 ≥1 件屋顶设备。
