# 第一部分 · 基线

## §0 已核实的事实（不要重新测，直接用）

### 0.1 PMX 在 babylon-mmd 里的真实尺度（实测）

方法：NullEngine 无头加载 PMX → 遍历全部 mesh，取逐顶点世界坐标的 Y 分布。
（脚本思路见 §11.2，可复现。）

| 模型 | 顶点数 | mesh 数 | 身体高度(1%~99% 分位) | Y 最大 |
|---|---|---|---|---|
| 星穹铁道—三月七3 | 25,042 | 32 | **19.69** | 20.39 |
| 星穹铁道—流萤·春日手信 | 23,710 | 31 | **19.96** | 20.67 |
| 星穹铁道—昔涟5 | 73,971 | 65 | **22.58** | 23.73 |

结论（写进代码注释，别再讨论）：
1. **1 个 babylon 单位 = MMD 原生单位**，babylon-mmd 不做米制换算；标准 PMX 身体高度 ≈ **20 单位**，脚底在 y≈0。
2. 根节点 `scaling = (1,1,1)`。
3. **一个 PMX 会被拆成 31~64 个 mesh**（按材质）。她一个人就占 30~60 个 draw call。
4. **包围盒有离群值**（有人量到 Y 上界 30 以上，是道具/杂项 mesh）。所以**量身高必须用分位数，不能用包围盒**。

## §1 需求

### 1.1 核心幻想

> **我小到可以被随意踩死，而她甚至不必注意到我。**

### 1.2 三条铁律

1. **加存在感，不加系统。** 只加三种：尺度感、她的存在感、玩家的主动性。
2. **这是玩具，不是工作。** 不做经营/成长/任务。
3. **每一版都能自己上手玩 2 分钟，并回答"这比上一版好玩吗"。**

### 1.3 明确不做

道具/消耗品（烟雾弹、护盾、加速、诱饵、投掷物）· 脚趾缝藏身 · 落地风压冲击波 · 踩扁弹回 · 胆子计分 · 震动分级 · 技能树/数值成长/等级 · 每日任务/签到 · 联机 · 巨人模式（操控她）· 拍照摆姿模式 · 天气与时间档切换（固定黄昏）。

### 1.4 两种模式

| 模式 | 规则 |
|---|---|
| **① 自由沙盒（默认进入）** | 不判负。被踩中 = 被推开 + 踉跄 + 演出。用来认路、看她、试躲法 |
| **② 生存逃脱（HUD 一键切换）** | 被踩中 = 结算。计"存活时间 + 擦身而过次数 + 最佳纪录"。一键重开 |

**必须先做①**：第一次进来的人要先看清这游戏有什么。

### 1.5 上手 2 分钟的体验脚本（做出来必须能对上这个剧本）

| 时间 | 玩家会看到 / 发生什么 |
|---|---|
| 0:00 | 第一帧就是黄昏的街道：有楼、有窗光、有雾、有远处天际线剪影。抬头——**她站在路口，遮住了半边天** |
| 0:05 | 她的影子从街对面扫过来，玩家意识到"她在动" |
| 0:15 | 摇杆走两步，脚下的路有路缘石，能踏上去；街边有路灯、垃圾桶、停着的车 |
| 0:30 | 她转头看向玩家（HUD 边缘泛红 + 心跳开始加速），脚步从远处逼近（方位声像） |
| 0:45 | 一只脚抬起，**脚影先落在地上并迅速变大变深**；玩家跑开，脚落在身旁砸出灰尘与震屏，一整片楼被压平 |
| 1:00 | 播报「擦身而过 +50」；车被踩成饼；消防栓喷水 |
| 1:30 | 玩家躲进巷子/车底，她的视线扫过没找到 → 播报「她失去了目标」，脚步远去 |
| 2:00 | 玩家自己想说"再来一次" |

### 1.6 验收线（逐条打勾）

1. 进入第一帧就能看见城市与地面（不是黑屏/纯色）。
2. 摇杆即走，不卡不飘；撞墙沿墙滑，不卡墙角。
3. 抬头能看到她的全身；**她比城里最高的楼还高**；她的影子压在街上。
4. 能读出她在看哪里，并能靠这个藏起来。
5. 被踩中有明确演出（脚影/震屏/灰尘/播报/慢动作）；沙盒模式不判负。
6. 跑一分钟也到不了城市边缘。
7. 截图不看 HUD，别人能认出"一座城市 + 一个巨人"，而不是"一堆盒子"。
8. 退出后回到原界面，**跟没进过一样**（连续进出 10 次，observer 数不变、帧率不降、画面不变暗）。

## §2 尺度系统

### 2.1 唯一常量 PH

```js
// game/scale.js —— 全项目唯一尺度入口, 别处一律不许出现裸数字
export const PH = 0.0543;      // 【锁定】玩家身高(世界单位) = 现状 expEyeH 0.05 / 0.92
export const u = (ph) => ph * PH;             // PH → 世界单位
export const inv = (units) => units / PH;     // 世界单位 → PH
export const PH_WALK = 3.0;    // 走
export const PH_RUN  = 9.0;    // 跑
export const PH_DASH = 20.0;   // 闪避冲刺
```

**她的换算**：`SHE = 20`（世界单位，实测），`SHE_IN_PH = 20 / PH ≈ 368`。
**她/玩家 = 368 倍。** 这是锁死的观感，不许改。

### 2.2 为什么玩家的速度不是"等比人类"（重要设计说明）

等比人类的速度是 0.9 PH/s。但她的脚掌椭圆是 **28 × 11 PH** —— 玩家要走 30 PH 才能从她脚下滑出去，等比速度需要 **33 秒**。这游戏就没法玩了。

所以：**玩家速度按"手感的绝对值"设，不按"等比缩放"设**：走 3 PH/s、跑 9 PH/s、冲刺 20 PH/s。
效果：看到她的脚抬起（约 3.5 秒下落时间）→ 跑 31 PH → **刚好能横向滑出她的脚掌**。这就是本作的核心操作窗口。
穿越城市（直径 125 单位 = 2300 PH）：跑速约 4 分钟，走速约 13 分钟 —— 一分钟绝对到不了边。

### 2.4 相机与阴影（照搬舞蹈场景的数值会全黑/漏光）

| 项 | 值 |
|---|---|
| `minZ` / `maxZ` | 0.0005 / 163 |
| `fov` | 0.9 |
| 相机高度 | 眼高 0.92 PH（蹲下 ×0.55） |
| 头部摆动 | 走路时 ±0.02 PH、频率 = 步频 ×2；跑动 ×2；停下 0.3 s 内归零 |
| 平行光 | 方向固定（黄昏低角度），`shadowMinZ 0.5`、`shadowMaxZ 60`、`bias 1e-5`、`normalBias 1e-4`、map 2048 |
| SSAO | **默认关闭** |
| Bloom | 保留，强度减半 |

### 2.5 运行时时序约定

- 她的朝向 = **模型 +Z**（与仓库现有约定一致：探索模式注释里"视线朝 +Z = 模型正脸"）。
- 她的位置 = 根节点 `root.position`（`container.meshes[0]`）；旋转只动 yaw（`root.rotation.y`），**不许动 scale**。
- 读脚骨允许**落后一帧**（16 ms，肉眼无感）：在游戏 observer 里读上一帧的骨骼快照。**不要动 MMD 的 observer 顺序**，那会引入不可预测的时序 bug。

# 第二部分 · 世界

## §3 城市施工规范

### 3.1 坐标系与朝向

- 世界左手系（Babylon 默认），**+Y 向上**。
- 城市原点 = **她站立的路口**（`(0,0,0)`），城市中心在原点。
- 她的朝向 = 模型 **+Z**（与仓库现有约定一致）。
- 所有半径/尺寸以**世界单位**存储，书写时用 PH 表达、经 `u()` 换算。

### 3.2 城市总布局（确定性）

```
城市格      : 28 × 28 个街区
街区 pitch  : 66 PH  (含街道) = 3.58 单位
城市总尺寸  : 28 × 66 = 1848 PH  = 100.3 单位   (半径 50 单位)
街道        : 次干道 = 车行道 5.5 PH + 两侧人行道各 1.6 PH = 街宽 8.7 PH
              主干道 = 车行道 9.0 PH + 两侧人行道各 1.6 PH = 街宽 12.2 PH
              每 4 条街升级为主干道 (即 index % 4 == 0)
街区净尺寸  : pitch − 街宽 = 57.3 PH (次干道) / 53.8 PH (主干道)
```

**分区块（按方位角，绕中心一圈）**
以原点为中心，按 `atan2(z, x)` 切成 5 个扇区（扇区边界加 ±6° 抖动避免呆板）：

| 扇区 | 方位 | 内容 |
|---|---|---|
| 商业区 | −90°~+10° | 高层 + 玻璃幕墙 + 霓虹招牌 + 底层商铺（密度最高） |
| 住宅区 | +10°~+110° | 低矮公寓 + 阳台 + 晾衣杆 + 空调外机 |
| 公园 | +110°~+170° | 草地、树、长椅、喷泉、儿童设施（**无楼**） |
| 工地 | +170°~+230° | 塔吊、围挡、钢筋堆、脚手架（半成品楼） |
| 水岸 | +230°~+270° | 河、桥、护栏、泊船 |

**中心广场**：原点周围 2×2 个街区清空为十字广场（她的脚下），铺广场砖 + 喷泉 + 花坛。玩家出生点也在这附近。

**主干道轴线**：4 条贯穿全城的主干道（x=±7, z=±7 街区索引），保证有长直视线。

### 3.3 建筑生成器（一栋楼 = 基座 + 标准段 + 顶部）

**输入**：街区块索引 `(bx,bz)`、沿边位置、朝向、分区、RNG 流。
**输出**：一串 AABB（写进碰撞世界）+ 一串几何（写进 tile 的 GeoBatch）。

| 步骤 | 规则 |
|---|---|
| 1. 体量 | 宽 `W ∈ [5, 12.5] PH`、进深 `D ∈ [5, 12.5] PH`、高 `H ∈ [7.5, 25] PH`（按分区取范围，§3.7）。**沿街面必须贴齐人行道内边**，不许歪进马路 |
| 2. 退台 | 概率 35%：把 H 切成 2~3 段，每段上层内缩 `[0.5, 2] PH`；退台段数写入 AABB（每段一个盒子，保证站在退台上不掉下去） |
| 3. 双体量 | 概率 25%：由两个不等高的盒子并排拼合（轮廓不再是一根方柱） |
| 4. 基座 | 底部 1~2 层（每层 2.2 PH）独立处理：玻璃门 + 暖色内透光 + 招牌色块 + 遮阳棚（挑出 0.5 PH 的薄板） |
| 5. 立面 | 用 §3.4 的 atlas 窗格子图，UV 平铺；`uScale = W / 开间宽`、`vScale = H / 层高`，**每栋楼从 4 套窗格变体里随机选 1 套** |
| 6. 顶部 | 女儿墙（高 0.4 PH 的一圈薄盒）**必然有**；屋顶道具（水箱/空调外机/通风管/天线/电梯机房）概率 45%，**只在距原点 600 PH 内的楼 + 主干道沿街楼**上生成（省面数） |
| 7. 材质 | 顶点色 tint（从分区色板取，±6% 明度抖动）+ 共享 atlas → 不产生新材质 |
| 8. 碰撞 | 每个盒子写一个 AABB；**退台的上层盒子顶面是可站立面** |

**每区块的楼数**：沿四边各放 1~3 栋（街区四边总长约 4×57 = 228 PH，平均楼宽 8 PH → 上限约 8 栋），实际取 4~8 栋。街区中心为内院（铺砖 + 少量绿化 + 停车位）。

### 3.4 程序化贴图：**唯一一张 1024×1024 atlas**（性能关键）

**全城所有静态几何共用一个材质。** 做法：离屏 canvas 画一张 1024×1024 图集，切 4×4=16 个 256×256 格；几何按"用哪一格"写 UV。

| 格 | 内容 | 画法 |
|---|---|---|
| 0 | 窗格 · 办公 | 底=墙色；层高 32px、开间 32px；窗 24×16px；点亮 15~30%（暖黄 `#ffd9a0` / 冷白 `#cfe6ff`）；每 4 层一条 2px 深腰线；每开间 1px 竖缝 |
| 1 | 窗格 · 公寓 | 同上但窗更小(20×20)、带 1px 窗台、点亮率 20~40% |
| 2 | 窗格 · 老城 | 木窗框、双扇、点亮率 30%，色调偏黄 |
| 3 | 玻璃幕墙 | 竖向明暗条 + 少量反射高光条，整面格 |
| 4 | 沥青 | 噪声点 + 2 条白虚线的图集版本（虚线单独格，见 5） |
| 5 | 车道线 | 透明底 + 白色虚线段（路面用第二层 UV 贴花或直接画在地面贴图里） |
| 6 | 广场砖 / 人行道砖 | 砖缝网格 + 轻微色差 |
| 7 | 草地 | 噪声绿 |
| 8 | 金属 | 竖向拉丝灰（栏杆/路灯/管道） |
| 9 | 玻璃门 | 深色玻璃 + 暖色内透渐变 |
| 10 | 招牌 A/B/C | 纯色底 + 简单几何图形（自发光层用它） |
| 11 | 围挡 | 黄黑斜条纹（工地） |
| 12 | 屋顶 | 防水层灰蓝 + 排水沟线 |
| 13 | 斑马线 | 白条 |
| 14 | 电线/护栏小件 | 纯色 |
| 15 | 软圆（脚影/接触阴影用） | 中心黑 → 边缘透明的径向渐变 |

**要求**：`wrapU/V = WRAP`、开 mipmap、各向异性 4；生成一次，全局复用；**场景里不允许出现第二张城市贴图**（她的模型贴图不算）。

### 3.5 路面 / 人行道 / 路口

- **车行道**：一整块地面（每 tile 一个 quad），贴沥青；每 tile 的 UV 平铺，交接处不打折（因为格网规则）。
- **人行道**：抬高 **0.094 PH** 的板 + 外沿一圈路缘石（高 0.094 PH，宽 0.2 PH）。**这一条高差是"城市感"的关键，也是碰撞系统里的真实台阶。**
- **路口**：斑马线（4 组）、停止线、转向箭头——全部画进 tile 的地面贴图 UV 区域（不增加几何）。
- **附属**：井盖（画在贴图里）、无障碍坡道（路口处的斜切几何，避免玩家被路缘卡住）。
- **地面至少 3 种材质分区**：车道 / 人行道 / 广场砖。

### 3.10 几何批处理与剔除（性能核心）

**不要用 `MeshBuilder.CreateBox` 生成上万个子 mesh**，也不要用 `MergeMeshes` 合并上千个 mesh（慢且爆内存）。
做法：**自己写几何累加器**。

```js
// geo.js
export class GeoBatch {                       // 一个 tile 一个
  constructor() { this.pos=[]; this.nrm=[]; this.uv=[]; this.col=[]; this.idx=[]; }
  addBox(cx,cy,cz, sx,sy,sz, yaw, atlasRect, tintRGB, opts={}) {...}   // 24 顶点/36 索引
  addQuad(p0,p1,p2,p3, atlasRect, tintRGB) {...}
  addCylinder(cx,cy,cz, r,h, seg, atlasRect, tintRGB) {...}
  toMesh(scene, name) {                       // VertexData → 一个 Mesh, 1 个材质
    const vd = new VertexData();
    vd.positions=this.pos; vd.normals=this.nrm; vd.uvs=this.uv;
    vd.colors=this.col; vd.indices=this.idx;
    const m = new Mesh(name, scene); vd.applyToMesh(m, false);
    return m;
  }
}
```

| 项 | 规定 |
|---|---|
| tile 划分 | **7×7 街区 = 462 PH ≈ 25 单位**；城市 28×28 街区 → **4×4 = 16 个 tile** |
| 每个 tile 的 mesh 数 | **1 个**（不透明；自发光件合并进同一个 mesh，用顶点色的自发光通道… 若 Babylon 标准材质不支持，则拆成 2 个：不透明 + 自发光） |
| 目标 draw call | 城市 **16~32**，她 31~64，脚影/贴花 3~5，天空 1，剪影 1 → **总计 < 110** |
| 目标三角 | 城市 **< 20 万**、她 ~5~20 万（取决于模型） |
| 手动剔除 | 每帧算 tile 到玩家距离，> 76 单位 → `setEnabled(false)`；剪影环始终开 |
| 生成时机 | 进入模式时按 tile 逐个生成（每次生成 1 个 tile 后 `await` 让出一帧），HUD 显示进度；**生成完缓存，二次进入不重建** |
| 生成耗时预算 | 全城 < 2.5 s（骁龙中端） |
| 内存预算 | 城市顶点数据 < 25 MB |

## §4 碰撞系统（"做得好"的落地）

### 4.1 为什么自建

| 方案 | 不用它的理由 |
|---|---|
| `scene.pickWithRay` | 城市是 batch 出来的大 mesh，射线贵；实例化/合并后拾取不稳定；每帧多次不可接受 |
| Babylon 物理引擎（Havok/Ammo） | 要加 wasm、要重标定全部参数，而我们只需要"圆柱 vs 静态盒子" |
| 她的 mesh 做碰撞 | 2.5 万~7 万顶点，射线太贵；且踩踏判定本来就该是解析式（§6.7） |

### 4.2 数据结构

```js
// collide.js —— 纯函数模块, 不 import babylon, 可在 Node 直接单测
export const CELL = 1.0;                 // 格网边长(世界单位)
const grid = new Map();                  // key = `${ix}_${iz}` → number[](AABB 下标)
```

- **地面** = 一块巨大的 AABB（`y ∈ [-1, 0]`，覆盖全城）→ 支撑判定统一走"顶面"。
- **人行道** = 抬高 0.094 PH 的长条 AABB；**路缘石** = 同高度的窄 AABB。
- **楼顶** = 楼的 AABB 顶面（所以能站上楼顶/退台）。

### 4.4 每帧解算（伪代码，照抄）

```js
function move(pos, disp, dt) {
  const SKIN = 0.02 * PH;            // 皮肤厚度, 防止贴面抖动
  // ---- 1) 水平: 分轴推进 ----
  pos = axisSweep(pos, disp.x, 0);
  pos = axisSweep(pos, 0, disp.z);
  // ---- 2) 台阶 ----
  // axisSweep 里被挡住的轴, 先尝试抬高 ≤ STEP_MAX (0.25 PH) 再试一次
  // ---- 3) 垂直 ----
  const supportY = maxTopFace(pos.x, pos.z, R);      // 所有"水平覆盖玩家"的 AABB 顶面最大值
  if (disp.y <= 0 && pos.y <= supportY + SKIN) { pos.y = supportY; vy = 0; onGround = true; }
  else { pos.y += vy * dt; vy -= GRAVITY * dt; if (hitCeiling(pos)) { vy = 0; } }
  // ---- 4) 头顶净空 ----
  if (hasCeiling(pos, H)) { /* 禁止起跳 / 阻止进入低矮空间 */ }
  // ---- 5) 她的腿: 推开但不阻挡 ----
  for (const cap of giantLegCapsules()) pushOutIfInside(pos, R, cap);
  return pos;
}

function axisSweep(pos, dx, dz) {
  if (dx === 0 && dz === 0) return pos;
  const block = query(pos.x, pos.z);
  const cand = { x: pos.x + dx, z: pos.z + dz };
  const pBox = playerAABB(cand, R, H, pos.y);
  for (const i of block) if (overlap(pBox, boxes[i])) {
    // 回退到刚好贴上(按轴), 保留另一轴 → 沿墙滑动
    if (dx !== 0) cand.x = (dx > 0) ? boxes[i].minX - R - SKIN : boxes[i].maxX + R + SKIN;
    if (dz !== 0) cand.z = (dz > 0) ? boxes[i].minZ - R - SKIN : boxes[i].maxZ + R + SKIN;
  }
  return { x: cand.x, y: pos.y, z: cand.z };
}
```

### 4.5 边界情况清单（逐条实现 + 逐条测试）

| 情况 | 处理 |
|---|---|
| 45° 斜冲墙 | 分轴推进天然沿墙滑行，保留切向分量 |
| 冲进两面墙的凹角 | 两轴都被挡 → 停在角上，不抖动（SKIN 吸收） |
| 路缘石 / 人行道 | 落差 0.094 PH ≤ STEP_MAX(0.25 PH) → 自动抬上去 |
| 从楼顶走下来 | 支撑面失效 → 转成下落（`vy` 从 0 开始） |
| 站在楼顶边沿 | 支撑面按 `maxTopFace` 取，走出边沿自然掉落 |
| 被退台卡住 | 退台每层都是独立 AABB，可以站上去（§3.3 步骤 2） |
| 高速冲刺穿墙 | 单帧位移 ≤ 冲刺速度 × dt ≈ 20×0.033 = 0.66 PH，小于最小楼宽 5 PH，**不会隧穿**；仍加断言：单帧位移 > 2 PH 时强制拆成多次 sweep |
| 出生点/复活点 | §5.5 校验 |
| 她在你身上 | 腿的胶囊把你推开（不阻挡、不卡死） |
| 走出城市 | 隐形墙挡住；HUD 提示"回城"箭头 |

### 5.3 相机

- 第一人称，眼高 `0.92 PH`（蹲 ×0.55）；`fov 0.9`；`minZ 0.0005`；`maxZ 163`。
- **头部摆动**：走路 ±0.02 PH、频率 = 步频 ×2；跑 ×2；0.3 s 内归零。
- **落地冲击**：着地时相机向下压 0.05 PH 并在 0.25 s 内弹回。
- **强制抬头**：当她进入 400 PH 内且正在下落时，相机 pitch 缓慢偏向她的脚（0.5 s 内最多偏 15°）——**这一条是"压迫感"的关键**。
- 抖动叠加：所有抖动在相机的最终 `position` 上叠加噪声偏移，**不改 rotation**（避免眩晕）。

### 5.4 出生点与复活点

```js
function findSpawn() {
  for (let i = 0; i < 20; i++) {
    const p = candidate(i);          // 围绕中心广场的候选点
    if (!insideAnyBox(p, 1 * PH) &&      // 半径 1 PH 内无实体
        hasSupport(p) &&                  // 脚下有支撑面
        !hasCeiling(p, 2 * PH)) return p; // 头顶净空 2 PH
  }
  return CENTER_SAFE;                 // 兜底: 中心广场预设安全点
}
```
**连续重开 20 次，无一次卡在几何体里。**

### 5.5 藏身（把体力活变成斗智）

**不需要手工打藏身点**：藏身 = **被遮挡**。

- 每 0.2 s 做一次视线采样：从她的眼位（头骨）到玩家，沿直线每 2 PH 采一点，查格网里有没有 AABB → 有 = 被遮挡。
- **被遮挡持续 0.5 s → 她失去目标 → 进入 `scan`**。
- **蹲下**：她的检测距离 ×0.5（`800 PH → 400 PH`），且在草丛/花坛后不会被扫描到。
- 生成器保证有足够的遮挡源：巷子（街区间的窄缝）、车与车之间、垃圾桶后、骑楼门洞、地下通道口（公园/水岸各一个）。

> ⚠️ 修正一个旧文档里的错误说法：**车底躲不进去**——车高 0.9 PH、离地净空只有 0.2 PH，玩家有 1 PH 高。能躲的是**车与车之间的缝隙**。

### 5.6 两种模式的规则

| 规则 | 沙盒 | 生存 |
|---|---|---|
| 直击（踩中） | 被推开 + 踉跄 + 播报"被踩到了"，不结束 | 结算 |

```js
const BONES = {
```

### 6.3 VMD 生成器（自造动作的唯一正确做法）

#### 6.3.1 文件格式（逐字节，已按 babylon-mmd 的 `VmdData` 核实）

```
[30] "Vocaloid Motion Data 0002"  (不足补 0x00)
[20] 模型名 (Shift-JIS, 补 0x00)          ← ⚠️ 必须是 Shift-JIS, 写 UTF-8 会匹配不上
u32  boneKeyFrameCount
  per frame:
    [15] 骨名 (Shift-JIS, 补 0x00)         ← ⚠️ 同上
    u32  帧号 (30 fps 基准)
    f32[3] 位置 (MMD 单位)
    f32[4] 旋转四元数 (x, y, z, w)
    i8[64] 插值参数(见下)
u32  morphKeyFrameCount
  per frame: [15] 表情名(Shift-JIS) + u32 帧号 + f32 权重
u32  cameraKeyFrameCount
  per frame: u32 帧号 + f32 距离 + f32[3] 位置 + f32[3] 旋转 + i8[24] 插值 + u32 视角 + u8 透视
u32  lightKeyFrameCount
  per frame: u32 帧号 + f32[3] 颜色 + f32[3] 方向
u32  selfShadowKeyFrameCount
  per frame: u32 帧号 + u8 模式 + f32 距离
u32  propertyKeyFrameCount (可写 0)
```

**64 字节插值参数的打包顺序**（照抄，这玩意写错就变成"匀速硬切"）：

```
X_x1,Y_x1,phy1,phy2,   X_y1,Y_y1,Z_y1,R_y1,   X_x2,Y_x2,Z_x2,R_x2,   X_y2,Y_y2,Z_y2,R_y2,
Y_x1,Z_x1,R_x1,X_y1,   Y_y1,Z_y1,R_y1,X_x2,   Y_y2,Z_x2,R_x2,X_y2,   Y_y2,Z_y2,R_y2, 00,
Z_x1,R_x1,X_y1,Y_y1,   Z_y1,R_y1,X_x2,Y_x2,   Z_x2,R_x2,X_y2,Y_y2,   Z_y2,R_y2, 00, 00,
R_x1,X_y1,Y_y1,Z_y1,   R_y1,X_x2,Y_x2,Z_x2,   R_x2,X_y2,Y_y2,Z_y2,   R_y2, 00, 00, 00
```
- 物理开关：`phy1=0x00,phy2=0x00` = 关物理；`phy1=0x63,phy2=0x0F` = 开物理 → **她的步态要开**（裙摆要动）。
- 缓动建议：脚落地用 `x1=20,y1=90,x2=20,y2=60`（快进慢出）；抬脚用默认 `(20,20,107,107)`。

#### 6.3.2 步态合成（treadmill，原地走）

**用 IK 骨驱动，不要硬掰大腿骨**（MMD 模型默认带腿部 IK，写 FK 会被 IK 拉回原状；写 IK 才是 MMD 动画师的正规做法）。

30 fps，**一个完整步态周期 = 60 帧（2 秒）**，左右脚各一个支撑相：

| 骨骼 | 通道 | 曲线（t = 0~1 为周期） | 说明 |
|---|---|---|---|
| 左足ＩＫ | z | 支撑相(0→0.6)：`+4.4 → −4.4` 单位线性；摆动相(0.6→1)：`−4.4 → +4.4` | 原地走的"跑步机" |
| 左足ＩＫ | y | 支撑相：`0`；摆动相：`1.2 × sin(π·t')` | 抬脚 1.2 单位 |
| 左足ＩＫ | x | 恒定 `+0.9` | 髋宽 |
| 右足ＩＫ | 同上 | **相位 +0.5** | |
| 左/右足首 | 旋转 | 支撑相前 15% 脚跟先落(X 轴 −12°)，末 20% 脚尖蹬离(X 轴 +25°) | 脚的滚动 |
| センター | y | `0.25 × sin(4πt)` | 每步一次起伏 |
| センター | x | `0.35 × sin(2πt)` | 左右重心转移 |
| 下半身 | 旋转Y | `7° × sin(2πt)` | 骨盆摆动 |
| 上半身 | 旋转Y | `−5° × sin(2πt)`；旋转X 恒定 `+5°` | 反向扭转 + 前倾 |
| 首/頭 | 旋转Y | `+3° × sin(2πt)` | 头部稳定 |
| 左腕/右腕 | 旋转X | `±18° × sin(2πt)`，相位与同侧腿相反 | 摆臂 |
| 左ひじ/右ひじ | 旋转X | `10° + 8° × sin(2πt)` | 肘部微屈 |
| 左肩/右肩 | 旋转 | `3° × sin(2πt)` | 肩部随动 |

**关键帧密度**：每 5 帧打一个关键帧（光滑 + 数据小），端点闭合（第 0 帧 = 第 60 帧）保证无缝循环。

**`idle`（90 帧 = 3 s）**：センター y `0.06×sin(2πt/3)`、上半身 X `+2°`、首 X `±1.5°`、双臂微摆、偶尔的头部转动放在随机帧上（同一个 VMD 每次播都一样，所以用两段 idle 交替）。

**`stomp`（90 帧 = 3 s，1.0 倍速播）**：

| 帧 | 阶段 | 内容 |
|---|---|---|
| 0–30 | 抬脚 | 右足ＩＫ y: 0 → 6 单位；センター x 偏移 −0.6（重心移到左腿）；上半身前倾 +8° |
| 30–45 | 悬停 | 脚停在 6 单位高度（**这就是玩家的逃跑窗口**） |
| 45–60 | 落下 | 右足ＩＫ y: 6 → 0，速度曲线陡（`x1=30,y1=95,x2=30,y2=100`）；センター 下沉 0.8 |
| 60–72 | 落地 | 落地那一帧脚 Y 触地（触发器看的就是这里），身体一晃，双臂上抬 |
| 72–90 | 收脚 | 回到与 `walk` 第 0 帧姿态接近的姿势（方便交叉淡化） |

#### 6.3.3 生成器的自检（写完必须跑）

1. **回读测试**：生成 → 用 babylon-mmd 的 `VmdData` 解析回来 → 断言：帧数、骨名集合、四元数模长 ≈1（误差 <1e-3）、帧号单调、首尾帧姿态一致（循环闭合误差 <1e-3）。
2. 用 NullEngine 加载她的 PMX + 生成的 VMD，**逐帧输出脚骨世界 Y**，画成曲线导出 PNG → 目视确认"支撑相脚不动、摆动相脚抬起"。
3. 输出 ASCII 骨架动画预览（每 3 帧打印一次双脚坐标）——沙箱里最省事的验证手段。

### 6.4 支撑脚接地驱动根位移（**不滑步的算法**）

```js
// 每帧(在游戏 observer 里, 读上一帧的骨骼快照即可)
const fl = footWorld('footL'), fr = footWorld('footR');
const support = (fl.y <= fr.y) ? fl : fr;           // 取低的那只
const airborne = Math.min(fl.y, fr.y) > GROUND_EPS;  // 双脚都离地 = 腾空相
if (!airborne) {
  const d = support.localDeltaXZ();                  // 相对上一帧的模型空间水平位移
  root.position.x -= d.x;                            // 抵消滑动 → 世界里的接触点静止
  root.position.z -= d.z;
  root.position.y = 0;                               // 她永远踩在地面平面
}
```
**边界情况**：

| 情况 | 处理 |
|---|---|
| 双脚都离地（跳跃/换脚瞬间） | 保持不动（不推进），避免抽搐 |
| 支撑脚切换的那一帧 | 用 0.15 s 的位移平滑（`lerp`）过渡，避免根节点弹一下 |
| VMD 里有"瞬移"帧 | 单帧位移 > 3 单位 → 视为异常帧，跳过不累计 |
| 播放速率变化 | 根位移自动跟着变（因为位移来自动画本身），**无需额外处理** |
| 原地转圈/抖动动作 | 加"位移小于 0.001 单位/帧则忽略"的死区 |

**结果**：她的移动速度**永远等于动作本身的步频**。要她走快 → 改 `animTimeScale`；要她停下 → 换 idle。**永远不会太空步。**

### 6.5 状态机

| 状态 | 动作 | 转移条件 |
|---|---|---|
| `idle` | idle（0.4 倍速） | 看见玩家(视线锥) 或 听到声音 → `approach` |
| `approach` | walk | 与玩家距离 < 300 PH → `stomp`；连续 3 s 看不见也听不到 → `scan` |
| `stomp` | stomp（1.0 倍速，一次播完） | 播完 → `recover` |
| `recover` | walk 首 20 帧 | 0.6 s → `approach`（若玩家被遮挡 → `scan`） |
| `scan` | idle + 原地转头 | 3 s 无发现 → `idle`；发现 → `approach` |

- **转向**：`root.rotation.y` 朝玩家插值，角速度上限 **35°/s**（她转身慢，你能看见她转过来）。
- **滞回**：进入/退出 `approach` 的判定阈值不同（发现 800 PH / 失去 900 PH），防止状态抖动。
- **节奏设计**：`idle` 与 `scan` 是玩家的安全窗口；`approach` 一启动就是危机重启。

### 6.6 感知

**视锥（含遮挡）**
```
看见 = 距离 < 800 PH
     && 夹角(她朝向, 玩家方向) < 35°
     && 视线未被遮挡(§5.5 的格网采样)
     && !(玩家蹲下 && 距离 > 400 PH)
检测代价: 每 0.2 s 一次, 采样点间距 2 PH → 最多约 400 次格网查询/次 → 可接受
```

**听觉（事件表）**

| 事件 | 半径 | 备注 |
|---|---|---|
| 跑动 | 400 PH（持续） | 走不发声 |
| 撞翻垃圾桶 | 700 PH | 一次性 |
| 踩碎玻璃（窗户碎屑） | 600 PH | 一次性 |
| 落水（水岸/喷泉） | 800 PH | 一次性 |
| 闪避翻滚 | 200 PH | 很轻 |

听到 → 转头朝声源方向，并进入 `approach`（若正在 `idle`）。

### 6.7 踩踏判定（核心 30 行）

```js
const landY = footRadius;                       // 触地阈值 ≈ 0.05 单位
const ev = (prevY > landY && nowY <= landY && (prevY - nowY) > 2.0);
if (ev) {
  const c = { x: now.x, z: now.z };             // 落脚点(地面投影)
  const yaw = footYaw;                          // 脚掌朝向(用脚骨或根节点的 yaw)
  const local = worldToFoot(c, yaw, playerPos); // 旋转到脚掌坐标
  const d = Math.hypot(local.u / (28*PH), local.v / (11*PH));  // 归一化椭圆距离
  if (d < 1.0)      -> 直击
  else if (d < 1.5) -> 擦身而过
  else              -> 未命中
}
```
- **双条件防误触发**：必须"Y 穿越 + 下降速度 > 2 单位/帧"同时成立；且同一只脚 **0.8 s 内只触发一次**。
- **预示（重要）**：每帧监控双脚 Y。当某只脚 **Y > 5 单位且垂直速度 < 0** → 立刻在它的地面投影处升起**脚影贴片**，尺寸随脚下降从 0.3 倍放大到 1.2 倍、不透明度 0.15 → 0.55。玩家以此判断"她要踩哪"。
- 玩家 `crouch` 时判定半径 ×0.6（潜行的物理奖励）。

### 6.8 破坏系统（把穿模变成玩法）

她的物理只有无限地面平面 → 楼一定穿模。**不对抗，改规则**：

| 触发 | 效果 |
|---|---|
| 落脚点所在街区块 | 该区块所有楼 **Y 缩到 5%**（200 ms 补间）→ 隐藏；邻近 8 个区块按距离 100~400 ms 延迟**依次**压扁（连锁） |
| 脚下的车 | 压成 0.1 倍高度的"饼"（保留 2 s 后淡出） |
| 脚下的消防栓 | 水柱喷发 6 s（一排薄片 + 粒子） |
| 脚下的水洼 | 溅水环 |
| 脚下的树 | 树冠飞散（12 片薄片，0.8 s 抛物） |
| 电线杆 | 半条街的自发光强度闪 3 次 |

**实现口径**：全部是"事件 + 视觉补间"，**没有一处真实物理**；街区级遍历一次即可，成本≈0。
楼被压扁后 **AABB 保留**（玩家依然站不上去也走不进去？——不，**压扁的楼 AABB 要移除**，让玩家能在废墟上跑，这是额外的爽点）。

### 6.9 慢动作

- 触发：`擦身而过` 或 `她进入 200 PH 内且正在下落`。
- 效果：动画推进倍率 → **0.25**，持续 0.5 s，然后 0.4 s 内回到 1.0。
- 实现：本项目 timeline 本来就是"真实时间 × 倍率"结构，改倍率极便宜（不要动 `engine.getDeltaTime`，会连带相机一起慢）。
- 同时相机 pitch 偏向她那只脚（§5.3 强制抬头）。

## §8 性能预算与降级

### 8.1 预算（目标 60 FPS，骁龙 7 系以上）

| 项 | 上限 |
|---|---|
| draw call | 城市 16~32 · 她 31~64 · 天空/剪影 2 · 贴花与粒子 5~10 · **总计 < 110** |
| 三角 | 城市 < 20 万 · 她 5~20 万 |
| 城市顶点内存 | < 25 MB |
| AABB 数 | < 12,000 |
| 每帧 JS（游戏逻辑，不含 Babylon） | < 2 ms |
| 视线采样 | 每 0.2 s 一次，单次 < 0.6 ms |

### 8.2 取舍顺序（超预算时从上往下砍）

1. 灰尘粒子片数 12 → 6 → 0
2. Bloom 关闭
3. 剪影环关闭
4. tile 剔除距离 76 → 55 单位（雾密度同步调大）
5. 城市格 28×28 → 22×22 → 18×18（改一个常量）
6. 她的物理 substeps 3 → 2（`__mmd.setPhysics`）
7. **最后才动**：她的布料物理整体关闭（关了就不"活"了，只在低端机上兜底）

### 8.3 必须常显的监控

HUD 右上角：`FPS / draw call / 三角 / 附近 AABB 数 / 她的状态名 / 双脚 Y`。
（`engine.getFps()`、`scene.getActiveMeshes().length`、`engine._drawCalls`。）

## §11 验收与自验

### 11.1 自验手段（不需要真机、不需要用户）

| 手段 | 能证明什么 |
|---|---|
| `node build.mjs` | 打包可过、无语法/依赖错误 |
| `node --test test/collide.test.mjs` | 碰撞系统正确性（10 条） |
| VMD 回读断言 | 自造动作文件合法 |
| NullEngine + PMX + VMD → 脚骨 Y 曲线 PNG | 步态自然（支撑相不滑、摆动相抬起） |
| **无头浏览器真渲染 → PNG → 像素判读** | 城市在不在、窗有没有亮、影子投没投、她在不在画面里、雾/天空/黄昏色温 |
| `scene.getActiveMeshes()` / draw call 计数 | 性能预算 |

**无头渲染的做法**：把 WebGL 帧缓冲 `readPixels` → 画进 2D canvas → `toDataURL` → POST 到本地小服务器 → 落盘 PNG（内置浏览器不能直接截 WebGL）。

**像素判读清单**：地平线以下的像素中"非地面色"占比 > 25%（有楼）· 画面内出现 ≥ 3 个高亮窗点 · 阴影区域平均亮度比非阴影区低 18% 以上 · 天空区存在顶部深蓝→地平线暖橙的渐变（取样 5 点）· 她的轮廓像素占画面 ≥ 2%。

### 11.2 复现尺度实测的方法（写进 §0 的那组数字）

NullEngine + `LoadAssetContainerAsync(File)` + 遍历 `container.meshes` 的 `getVerticesData("position")` 经世界矩阵变换后统计 Y 分位数；
Node 里需要给 `FileReader` 打 polyfill，并把材质构建器的 `_textureLoader` 换成空实现（不加载贴图）。脚本可作为 `tools/measure-pmx.mjs` 入库。

### 11.3 只有真机能验的（交给用户）

手感（走速/转身/翻滚跟手度）· 真机帧率 · 散热降频后表现 · "踩下来那一下有没有压迫感"。
**流程**：交付 APK 产物 → 用户装上看 → 一句"卡/穿模/不好玩" → 定位由我（执行者）完成。

### 13.3 术语

- **PH**：玩家身高，本方案唯一尺度单位（1 PH = 0.0543 世界单位）。
- **tile**：城市分块（7×7 街区），一个 tile 一个合并 mesh，用于剔除与合并。
- **atlas**：全城共用的 1024×1024 程序化贴图集。
- **支撑脚接地驱动根位移**：从动画里提取根位移的技术，保证接触点在世界上静止（不滑步）。
- **支撑相 / 摆动相**：脚踩地的阶段 / 脚离地摆动的阶段。
