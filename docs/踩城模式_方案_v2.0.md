## 0. 先说三条实测事实（本方案建立在这上面）

**事实 1 · PMX 在 babylon-mmd 里是 MMD 原生单位，标准模型 ≈ 20 单位高，脚底在 y≈0。**

我在沙箱里用 NullEngine 实跑了三个不同的 PMX，量的是逐顶点世界坐标：

| 模型 | 顶点数 | 身体高度（1%~99% 分位） | Y 上界 |
|---|---|---|---|
| 星穹铁道—三月七3 | 25,042 | **19.69** | 20.39 |
| 星穹铁道—流萤·春日手信 | 23,710 | **19.96** | 20.67 |
| 星穹铁道—昔涟5 | 73,971 | **22.58** | 23.73 |

根节点 `scaling = (1,1,1)`——**babylon-mmd 不做米制换算**。同时量到一个重要事实：**一个 PMX 会被拆成 31~64 个 mesh**（按材质分），这个数字后面要用来做性能预算。

**事实 2 · 现有「探索模式」的玩家尺寸 = 本方案的尺度锚点。**

```
expEyeH      = 0.05     // 眼高
expWalkSpeed = 0.03     // 行走（UI 滑杆 0.01~3，可存 localStorage）
```
眼高 0.05 单位 ÷ 她的 20 单位 → **你 = 她的 1/368**。这就是你说的"现在的大小刚刚好"，**本方案原样锁定，一个数都不改**。
（顺带：这也解释了"随便走几步就走到边缘"——地面只有 40×40 单位，滑杆拉到上限 3 单位/秒时 13 秒就能横穿。城市必须扩大两个数量级。）

**事实 3 · 缩放她的模型 = 崩。**

她的裙摆/头发物理、IK、VMD 位移全部是 MMD 原生尺度标定过的。**她的 `scaling` 永远 = 1，绝不碰。** 要巨人感只有一条路：**把她周围的世界做小**——也就是"把玩家缩小"。

## 1. 要什么（需求）

### 1.1 核心幻想

> **我小到可以被随意踩死，而她甚至不必注意到我。**

所有设计必须能追溯回这一句。追溯不回去的，不做。

### 1.2 三条设计铁律

1. **加存在感，不加系统。** 只加三种东西：尺度感、她的存在感、玩家的主动性。
2. **这是玩具，不是工作。** 不做经营、成长、任务那一套。
3. **每一版都要能自己上手玩 2 分钟，并回答："这比上一版好玩吗？"**

### 1.3 明确不做（已被明确否决，防止再被加回来）

| 不做 | 原因 |
|---|---|
| 道具 / 消耗品（烟雾弹、护盾、加速饮料、诱饵、投掷物…） | 会把玩法从"玩她"变成"玩道具栏" |
| 脚趾缝藏身 / 落地风压冲击波 / 踩扁弹回 / 胆子计分 / 震动分级 | 用户明确移出 |
| 技能树 / 数值成长 / 等级 / 每日任务 / 联机 | 玩具变工作 |
| 巨人模式（玩家操控她踩 NPC）/ 拍照摆姿模式 | 本版不做，先把"被她踩"这一件事做透 |
| 本版不做天气与时间档切换 | 固定**黄昏**一种（夜景的窗光 + 灯箱全部保留，只是不切档） |

### 1.4 玩法（两种，进入即玩）

| 模式 | 说明 |
|---|---|
| **① 自由沙盒（默认进入）** | 她走她的，你逛你的。被踩到只是被推开/踉跄，不判负。用来认路、看她、试躲法 |
| **② 生存逃脱（HUD 上一个按钮切换）** | 被踩中 = 结束，结算"存活时间 + 擦身而过次数"。重开一键 |

**默认必须是沙盒**：第一次进来的人要先"看清楚这游戏到底有什么"。

### 1.5 验收线（做完逐条打勾）

1. 进入第一帧就能看见城市与地面（不是黑屏、不是纯色背景）。
2. 摇杆按下去人就走，不卡不飘不穿墙；撞墙会沿墙滑，不会卡在墙角。
3. 抬头能看到她的全身，**她比城里最高的楼还高**；她的影子压在街上。
4. 你能读出她在看哪里，并能利用这个躲起来。
5. 被踩中有明确演出（脚影/震屏/灰尘/播报），沙盒模式下不判负。
6. 走一分钟也走不到城市边缘。
7. 截图不看 HUD，别人能认出"一座城市 + 一个巨人"，而不是"一堆盒子"。
8. 退出后回到原来的 MMD 播放界面，**跟没进过一样**（连续进出 10 次，observer 数不变、帧率不降、画面不变暗）。

## 2. 尺度系统（一切的前提）

### 2.1 唯一常量：PH

```js
// scale.js —— 全项目唯一尺度入口
export const PH = 0.0543;        // 【锁定】玩家身高 = 0.0543 单位 (= 现状 expEyeH 0.05 / 0.92)
export const u = (ph) => ph * PH;   // 以"玩家身高"为单位 → 世界单位
```

**所有设计数据一律用 `PH`（玩家身高）为单位写，代码里过 `u()`。禁止裸数字。**

> 为什么要用 PH 而不是"米"：因为 PH 与你实际看到的画面 1:1 对应，改手感只改这一个数。
> 如果你哪天说"她太大/太小了"，我只改 `PH` 一个值就能整体挪，其余代码一行不动。

### 2.2 换算总表（照这个写代码）

| 玩家碰撞半径 | 0.3 | 0.0163 | 圆柱 |
| 走 / 跑 / 蹲行 | 0.9 / 2.8 / 0.45 /秒 | 0.049 / 0.152 / 0.024 | 真人步频比例 |
| 跳（可选动作） | 初速 4.6/s | 0.25 | 重力 12 PH/s² |
| **她** | **368** | **20** | 模型原生，`scaling=1`，绝不碰 |
| 她的脚掌半径（判定） | 半长 28 / 半宽 11（椭圆） | 1.5 / 0.6 | 见 §6.4 |

### 2.3 相机与阴影参数（照搬舞蹈场景的数值会全黑或漏光）

- `camera.minZ = 0.0005`、`camera.maxZ = 163`、`fov = 0.9`
- 平行光阴影：`shadowMinZ = 0.5`、`shadowMaxZ = 60`、`bias = 1e-5`、`normalBias = 1e-4`、`shadowMap = 2048`
- SSAO **默认关闭**（手机太贵），Bloom 保留但强度减半

## 3. 世界与城市（要"精致"，不要"一堆盒子"）

> 硬约束：**不引入任何外部模型/贴图/音频文件**（包体可控、无版权风险、不入库资源）。
> 全部用 `MeshBuilder` + **程序化贴图**（离屏 canvas 画窗格/砖缝/沥青/标线 → `DynamicTexture`）+ **WebAudio 程序化音效**。
> **精致 ≠ 面数多**，而是层次、重复中的变化、材质、光影。

### 3.1 城市布局（确定性生成）

- **确定性随机**：用固定种子的 mulberry32，**同一个种子永远生成同一座城**（便于反复验证与截图对比）。
- **五大分区**（按方位角分扇区，绕中心一圈）：商业区（高层+玻璃幕墙+霓虹招牌+底层商铺）／住宅区（低矮公寓+阳台晾衣杆空调外机）／公园（草地、树、长椅、喷泉）／工地（塔吊、围挡、钢筋堆、脚手架）／水岸（河、桥、护栏）。
- **她站在城市正中央的十字路口**；玩家出生点在离她 **200~300 PH**（约 11~16 单位）的同一条街上——**抬头就能看见她**。
- **街道格网**：主干道（宽 4.4 PH）+ 次干道（3 PH），十字路口全部对齐，保证没有"歪进马路"的楼。

### 3.2 建筑生成器（核心，一栋楼 = 基座 + 标准层 + 顶部）

- **体量**：宽/进深 5~12.5 PH、高 7.5~25 PH；支持**退台**（上层内缩形成阶梯轮廓）与**双体量拼合**（轮廓不是单一立方体）。
- **立面**：程序化窗格贴图——按层高与开间画窗洞，**随机点亮 15~30% 的窗**；加窗台线、腰线、竖向分隔条。
- **底座（1~2 层）**：商铺/大堂，**独立材质**（玻璃门 + 暖色内透光 + 招牌色块 + 遮阳棚），与上部明确区分。
- **顶部**：女儿墙 + 随机屋顶道具（水箱、空调外机、通风管、天线、电梯机房）。
- **色板**：商业区偏冷灰蓝 / 住宅区偏暖米 / 老城偏黄褐。窗格密度、退台层数、屋顶道具组合都随机。
- **数量**：约 1200~1600 栋（35×35 街区，每块 1~3 栋）。

### 3.3 路面 / 人行道 / 街具（"精致度"的关键，别省）

- **车道**：沥青深灰 + 程序化贴图（虚线、实线、磨损、油渍、补丁）。
- **人行道**：**必须抬高 0.094 PH（4~5 cm 世界单位）**，铺装格子贴图。这一条"高差"是极廉价的"城市感"来源，且给碰撞系统一个真实的台阶。
- **路口**：斑马线、停止线、转向箭头（路面贴花）。
- **街具（≥12 种，沿街按固定间距自动布置）**：路灯（灯杆+弯臂+灯头，夜间发光+地面光斑）、行道树、信号灯、路牌、长椅、垃圾桶、消防栓、公交站牌/雨棚、花坛、护栏、广告灯箱、电线杆+下垂电线（`LinesMesh`，极便宜但观感提升明显）。
- **车**：路边停车为主（可被踩扁成"纸箱"）。
- **地面至少 3 种材质分区**（车道 / 人行道 / 广场砖），不许一块纯色平面。

### 3.4 天空 / 雾 / 光

- **黄昏天空**：渐变（顶部深蓝 → 地平线暖橙），用一个反置的大球 + 程序化渐变贴图。
- **雾必须开**（EXP2）：出纵深 + 遮远景接缝。
- **主光 = 平行光（太阳），必须开阴影**：她的巨大阴影投在街上和楼上，**这是"巨人感"的第一来源**。
- **半球光**避免暗部纯黑；窗光/灯箱用自发光材质，夜景氛围全在贴图里。
- **她的阴影**：只有她的模型投射、城市**只接收不投射**（省一半 shadow map 成本）。

### 3.5 性能：区块化（城市能做大全靠这个）

- **切块**：城市按 **4 单位见方** 切块（约 30×30 个块），**每块内部把楼体/路面/街具全部 merge 成一个 mesh**。
  → 视锥剔除按块生效，**同屏 draw call 稳定在 30~60**，与城市总大小无关。
- **贴图**：窗格/沥青/砖缝各生成一张（256~512），**全城共用材质**（每种材质 1 张，不要每栋一张）。
- **远景剪影环**：60 单位外一圈低模剪影（无窗、单色、受雾），撑天际线。
- **坐标原点**：不要让坐标跑到几万（float 精度会抖）——城市原点就在中心，总半径 60 单位，安全。
- 预算（骁龙 8 级，60 FPS 目标）：同屏三角 < 25 万、draw call < 80、她自己的模型 31~64 个 draw call 已占一部分，城市必须让路。

## 4. 碰撞系统（要求"做得好"，所以自己写，且能在沙箱里测）

### 4.1 为什么不用现成方案

- **不用 `scene.pickWithRay`**：城市是合并 mesh + 实例化的，射线既贵（每帧多次）又不稳定（命中面片精度、实例化拾取）。
- **不用 Babylon 物理引擎**：引入 Havok 要加 wasm、要重标定所有参数，收益为负（我们只需要"人 vs 静态盒子"）。
- **不用她的 mesh 做碰撞**：她的模型 2.5 万~7 万顶点，射线太贵。

### 4.2 世界表示：格网哈希 + AABB 表

```js
// collide.js
// 每个固体 = 一个 AABB {minX,minY,minZ,maxX,maxY,maxZ, tag}
// 生成城市时一并写入格网哈希: key = `${floor(x/CELL)}_${floor(z/CELL)}`, CELL = 1 单位
// 查询: 取玩家周围 3×3 个格子的全部 AABB（几十个），逐帧全测
const CELL = 1.0;
export function addBox(box) { /* 写入 boxes 数组 + 格子索引 */ }
export function query(x, z, r) { /* 返回附近 AABB 列表 */ }
```
**这个世界里"地面"也是 AABB**：y=0 的大平面 = 一块巨大的 AABB；人行道 = 抬高 0.0051 的块；楼顶 = 楼的 AABB 顶面。**所有支撑判定统一走 AABB 顶面**，不需要任何射线。

### 4.3 玩家 = 圆柱（半径 0.3 PH、高 1 PH）

每帧移动按下面顺序解算，**分轴推进**：

1. **水平（先 X 再 Z）**：把玩家圆柱当作 AABB（`±r`）扩张，与附近所有 AABB 做重叠测试；
   命中则该轴回退到"刚好贴上"的位置（沿面滑行），**另一轴照常走** → 撞墙不卡、能沿墙滑、拐角不会被卡住。
2. **台阶**：如果只为了一点高度差挡住，且落差 ≤ **0.25 PH**，直接抬上去（人行道 0.094 PH 一步可上）。
3. **垂直**：取所有"水平覆盖玩家"的 AABB 顶面最大值 = 支撑高度；玩家 y 向它靠拢（上楼下楼都能站）。
4. **头顶**：向上 1 PH 内若有 AABB 底面，视为"过头顶"，禁止跳（或站着也进不去）。
5. **世界边界**：城市外圈放一圈隐形墙（AABB），**撞上去会被挡住但不会卡死**（沿墙滑开）。
6. **她的腿**：用骨骼位置生成 2 个胶囊（左/右小腿 + 脚），玩家撞上被**推开**（不许穿进她身体里，那会毁掉存在感），但**不阻挡**（她不会把你卡住）。

### 4.4 必须写的自测（沙箱里跑，不依赖手机）

把 `collide.js` 写成**纯函数模块**（不 import babylon），在 Node 里跑一组自动化用例：

- 直冲墙面 → 停在墙前 δ 内，不穿墙；
- 斜 45° 冲墙 → 沿墙滑动，位移的切向分量保留 ≥ 80%；
- 冲楼梯/人行道 → 能上去；
- 沿街角内外绕一圈 → 不卡住、不抖动（连续 600 帧位置连续，无跳变 > 0.2 PH）；
- 从楼顶边缘走下 → 平滑落到地面；
- 随机游走 10 万步 → 永远不出城市边界。

**这是本方案唯一能在沙箱里 100% 完成验证的子系统，必须做到全绿。**

## 5. 玩家（你）

### 5.1 控制器

复用现有探索模式的数学（yaw/pitch 手性、防自转根治、单例 observer + `cityActive` 守卫），**改四处**：

1. 数值全部从 PH 推导（`eyeH = u(0.92)`、`walk = u(0.9)/s`、`run = u(2.8)/s`）——**绝不沿用 0.05 / 0.03**。
2. 碰撞走 §4 的 AABB 世界，不用射线。
3. 输入：摇杆（左半屏）+ 视角（右半屏）+ 跑（摇杆推满即跑）+ 蹲（按钮）。
4. 相机加到碰撞：相机贴地仰拍时不能钻进地面/楼里（相机与玩家同点起步，向上按 0.92 PH 起算，遇阻挡拉近）。

### 5.2 动作

| 动作 | 说明 |
|---|---|
| 走 / 跑 | 摇杆驱动，速度按 PH 推导 |
| **闪避翻滚** | 短冲刺 + 0.25 s 无敌帧，**躲踩的核心手感**（方向 = 摇杆方向，冷却 1.2 s） |
| 蹲 | 视高 ×0.55，**被踩判定半径 ×0.6**（潜行的物理基础） |
| 跳 | 可选（初速 4.6 PH/s，重力 12 PH/s²），能跳上人行道/矮台阶 |
| 踉跄 | 她在近处落脚时，玩家被震得偏移一小段（纯演出，不失控） |

### 5.3 出生点校验（必须有，否则"进游戏黑屏/卡在楼里"会重现）

候选点 → 检查：脚下有支撑面、半径 1 PH 内无 AABB、头顶 2 PH 净空 → 不满足就沿街重试（最多 20 次）→ 兜底到"城市中央大道路口的安全点"。
**连续重开 20 次，无一次卡在几何体里。**

### 5.4 藏身（把玩法从体力活变成斗智）

可藏身点由生成器打标：垃圾桶后 / 车底 / 门洞 / 巷子死角 / 地下通道口。
进入藏身 = 位移不再被她的视线锥捕获，且她**失去目标 → 进入搜索**（见 §6.3）。

## 6. 她（巨人）

### 6.1 动作来源：**用你导入的 VMD，播放必须自然**

她的一切动作都由 **VMD 驱动**（MMD 动作本身就是动捕级，这是"自然、真实"的唯一可靠来源）。游戏模式**不写程序化走路动画**——程序化走路一定假。

- 进游戏前，玩家在文件库里挑好动作（现有能力，`MmdFileRuntimeModelAnimation` 三轨都在）。
- 动作**按用途分槽**：`idle`（待机/缓慢循环）、`walk`（走路）、`stomp`（踩踏，可选）、`dance`（兜底：任何动作）。
- **缺槽策略**：没有 `walk` 就用 `dance` 平移；没有 `stomp` 就用 `walk` 的高抬腿段。**任何情况下游戏都能跑起来，不会因为缺资源卡住。**
- **切换用交叉淡化**（`MmdCompositeAnimation` 的 span 已支持）：0.4 s 淡入淡出，**不许硬切**（硬切 = 一眼假）。

### 6.2 不滑步（"自然"的技术底线）

她的动作是原地动画，靠**支撑脚接地驱动根位移**，绝不用"固定速度硬推"：

```
每帧（在 MMD 更新之后读取脚骨世界坐标）:
  取双脚中"最低"的那只作为支撑脚 support
  若 support 处于支撑相(其 Y < 站立阈值):
      Δ = support 本帧的水平位移(相对上一帧, 模型空间)
      root.position -= Δ        // 抵消滑步 → 接触点在世界里静止
  否则: 不动(腾空相)
```
结果：**走路速度自动等于动作本身的步频步幅**，永远不会滑步、不会走"太空步"。
要她走快走慢 → 改**动画播放速率**，根位移会自动跟着变。

> ⚠️ 时序：脚骨的世界矩阵在 MMD 的 `beforePhysics` 阶段后就是最终值。
> 实现时**允许判定落后一帧（16 ms，肉眼无感）**，用 `onBeforeRenderObservable` 里注册的游戏 observer 读前一次的骨骼快照即可——**不要为了抢一帧去动 MMD 的 observer 顺序，那会引入不可预测的时序 bug。**

### 6.3 行为状态机

```
idle     待机: 播 idle(0.5 倍速), 偶尔转头
approach 接近: 播 walk, 根位移由支撑脚驱动, 朝向玩家
stomp    落脚: 播 walk 的落脚段(或 stomp 槽), 触发落地判定
recover  收脚: 播 walk 的抬脚段
scan     搜索: 停住, 原地转头扫视(玩家藏身后进入; 找不到 → 回 idle)
```
- **转向**：根节点 yaw 向玩家插值，角速度限制（不许瞬转）——她转过身来，你能看到。
- **视线锥**：她朝向 ±35°、距 800 PH 内 = 看得见你。**必须有 HUD 提示**（一个箭头/边缘泛红），否则玩家读不出来。
- **听觉**：跑动、踩碎屑、撞翻垃圾桶 → 她在 1.5 s 内转头朝声音方向。**跑得快 = 更容易被发现**（潜行的另一半）。

### 6.4 踩踏判定（全项目最核心的 30 行）

```
每帧读脚骨(左足首/右足首)世界坐标, 与上一帧比较:
  落地事件 = (prevY > landY) && (nowY <= landY) && (prevY - nowY > u(2))
  落脚椭圆中心 = (now.x, now.z), 半长 28 PH / 半宽 11 PH (随朝向旋转)
  判定(玩家位置投影到椭圆坐标):
    d < 1.0  → 直击(生存模式结束 / 沙盒模式踉跄+扣血表现)
    d < 1.5  → 擦身而过(加分 + 播报 + 慢动作)
```
- 骨骼名按 **MMD 原名**取：`左足首` / `右足首` / `左つま先` / `右つま先`（babylon-mmd 的 `MmdModelLoader` 保留日文原名；`左足` = 膝盖、`左足首` = 脚踝）。
- **不用射线打她的 mesh**，全解析式 → 零性能成本，且判定稳定。
- 阈值全部写在 `config.js`，真机手感只调这一处。

### 6.5 她带来的破坏（把"穿模"变成玩法）

她的物理只有一条**无限地面平面**——她一定会穿楼。**不对抗，改规则**：

> **她落脚点所在街区块内的楼 → 触发式压扁**（Y 缩到 5%，200 ms 补间后隐藏），邻近街区 100~400 ms 内**依次压扁**（连锁）。
> 判定是**街区级**的（一次遍历），零物理成本；玩家看到的是"楼被踩平了"。

同一套机制顺手给出：
- 踩到车 → 车压成饼（最好的尺度感演示）；
- 踩到消防栓 → 水柱（一排薄片 + 粒子）；
- 踩过水洼 → 溅水。
**全部是"触发 + 视觉"，没有一处需要真实物理。**

### 6.6 慢动作特写（她已经踩到你身边时）

- **不要只在"被踩中"才慢动作**（那是惩罚）。**擦身而过时也要慢**——让玩家看清那只脚离自己有多近。
- 实现：把动画 timeline 的推进倍率降到 0.25（本项目 timeline 本来就是"绝对时间 × 倍率"结构，改倍率极便宜），持续 0.5 s。
- 机位：**贴地仰拍**那只压下来的脚，背景是她遮住天空的身体——这一帧就是这游戏最值得截图的地方。

### 8.3 生命周期（零残留是硬指标）

```
enterCityMode():
  1. 存档: 主相机状态 / activeCamera / ground.enabled / 她当前的动画句柄与位置 / 现有 UI 可见性
  2. 挂起 postProcess (_suspendPostProcess)
  3. 清场: 隐藏舞蹈地面(40×40)与舞台; 隐藏播放条/导出/画幅工具
  4. 建城(首次生成后缓存; 二次进入不重建)
  5. 她的位置移到城市中央, 挂上游戏状态机
  6. 玩家相机启用, 出生点校验后放置
  7. 注册【单例】game observer(首行守卫 if (!cityActive) return;)
  8. HUD 显示

exitCityMode():
  1. cityActive = false(observer 立即空转)
  2. 移除 observer(失败无害)
  3. 逐项还原步骤 1 的存档 + 恢复 postProcess + 恢复主 UI
  4. 解除游戏对动画时间轴的接管(交还播放器)
  5. HUD 隐藏

硬指标: 连续进出 10 次 → observer 数不变、帧率不降、画面不变暗、她回到原位。
(HUD 角标常驻打印 observers.length 供自测)
```

| 风险 | 对策 |
|---|---|

## 13. 开工前唯一需要你确认的一件事

**默认参数已按"现在的大小刚刚好"锁定：`PH = 0.0543`（= 现状探索模式的眼高 0.05 / 0.92）。她 = 你的 368 倍。**

如果你之后觉得"她该再小一点 / 再大一点"，**只改 `PH` 一个数**，整座城、所有速度、所有判定半径会一起等比变化，不需要改第二行代码。
