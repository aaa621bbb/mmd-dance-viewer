## §1 输入与相机（灵敏度可控、松手即停）

### 1.1 现在的毛病与根因

- 现在 `yaw += lookDX * 0.006 * sens`：**每帧直接加**，没有"松手后归零"，也没有衰减。
- `lookDX` 来自触摸移动事件的累计值；**手指抬起时若没有清零或还有残余事件**，就会持续转。
- 没有角速度上限：手指快速划一下 → 单帧巨大增量 → 转很久。
- 灵敏度只有一个全局系数（0.2~4），**水平/垂直不分开**，无法按手感调。

### 1.2 改法（速度式输入 + 指数衰减 + 限幅）

```
每帧:
  yawRate_target = lookDX_norm * SENS_H * MAX_RATE        // SENS_H: 0.2~3.0 (滑杆)
  pitchRate_target = lookDY_norm * SENS_V * MAX_RATE
  yawRate += (target - yawRate) * (1 - exp(-dt / TAU))    // TAU: 跟手度, 默认 0.05s
  yawRate *= exp(-dt / TAU_STOP)                          // 松手后 TAU_STOP=0.06s 内衰减到 ~0
  yawRate = clamp(yawRate, -MAX_RATE, +MAX_RATE)          // MAX_RATE = 240°/s (可调 120~360)
  yaw += yawRate * dt
触摸结束/取消 → 立即把 target 与 rate 置 0（touchend / touchcancel / pointercancel 三处都要）
```

### 1.3 必须做的细节

| 项 | 规格 |
|---|---|
| 灵敏度滑杆 | **水平 / 垂直分开**，0.2~3.0（默认 1.0），`localStorage` 持久化 |
| 最大角速度 | 滑杆 120~360 °/s，默认 240（这是"划一下会不会飞出去"的闸门） |
| 惯性 | 滑杆 0~1（默认 **0.15**，接近"跟手"）；0 = 松手立刻停 |
| 死区 | 触摸位移 < 2 px 忽略（防抖） |
| 多点触控 | 摇杆与视角区互斥：谁的 touchstart 落在哪半屏就归谁，另一个手指不干扰 |
| 复位键 | HUD 上一个"视角归零"按钮（万一还是转飞了，一键恢复） |
| PC | 鼠标锁定后 `movementX/Y` 同样走上面的模型；另给 DPI 缩放与"反转 Y"开关 |
| 调试 | HUD 角标常显 `yawRate °/s`，真机调参只看这个数 |

### 1.4 验收

1. 手指在屏幕上划一下后**松手，0.3 秒内角速度必须 < 1°/s**（用 §1.3 的角标读数验，可自动化）。
2. 灵敏度滑杆拉到 0.2 与 3.0，同等手势的转动角度相差 ≥ 5 倍。
3. 长按不放不做任何移动 → 视角**完全不转**（这条现在是不成立的，必须成立）。

## §2 贴地与碰撞正确性（悬空 + 穿墙）

### 2.1 悬空（楼板不接地面）——根因与改法

**根因**：物件的高度基准**混用**了两种写法：有的用"中心 y = H/2"，有的用"H/2 + 基座抬高"，有的忽略了人行道抬高 0.094 PH，有的退台段累加 y 起点出错。结果是楼、车、路灯、花圃各自悬在不同高度。

**改法（一刀切，不许例外）**：

```
所有几何一律由「底面 y」定义，而不是「中心 y」：
  addBoxOnGround(x, z, W, D, H, zBase, yaw, ...)   // yBase = 该点支撑面高度
  → 内部一律 cy = yBase + H/2
支撑面高度 yBase 由统一函数取：
  yBase = groundHeightAt(x, z)   // 路面 0 / 人行道 0.094PH / 广场砖 / 楼顶(退台)
生成后强制自检：每个物件的 AABB.minY 与 groundHeightAt(中心) 之差必须 < 0.01 单位
```

**自检必须自动化**（`tools/audit-city.mjs`，在 Node 里跑同一套生成代码，不需要 GPU）：
- 输出**悬空清单**：`minY - yBase > 0.01` 的物件（类型/坐标/差值），一次性列出所有。
- 输出**陷地清单**：`minY - yBase < -0.01`（陷进路面）。
- 两条清单必须为空，才算过关。

### 2.2 穿墙 —— 根因（这条最关键）

**根因：可视几何带 yaw 旋转，碰撞 AABB 却按未旋转的 W×D 算。**

街区块沿四条边布置，北/南边与东/西边的楼朝向差 90°。几何用了 `addBox(..., yaw, ...)` 旋转，但碰撞盒子写的是
`minX = cx - W/2, maxX = cx + W/2`——**宽深没有互换**。
结果：楼的"看得见的部分"有相当一块**没有碰撞盒**（可以走进去 = 穿墙），而另一些看不见的地方**有碰撞盒**（撞空气）。

**改法（同源，不给第二次犯错的机会）**：

```
一个函数同时产出几何与碰撞：
  addSolid(batch, collideBoxes, x, z, W, D, H, yBase, yaw, rect, tint, kind)
    → 几何: batch.addBox(..., yaw, ...)
    → 碰撞: 把 (W/2, D/2) 经 yaw 旋转后的四角取包围盒（yaw=±90° 时自动变成 D×W）
街具（圆柱类的路灯/树/消防栓）、车（带 yaw 的盒子）、护栏、花坛、公交雨棚 全部走这一个函数。
```

### 2.3 生成后一致性自检（把"穿墙"变成可测的量）

1. **AABB 覆盖检验**：对每个 AABB，取它四条边中点向内侧偏移 0.02 单位，做一次"点是否在可视几何内"的射线测试（`scene.pickWithRay` 只在离线审计时用，不进运行时）；不匹配率必须 < 0.5%。
2. **穿透检验**：在 `.mjs` 单测里跑"贴墙滑行"用例：从 8 个方向贴墙推进 600 帧，玩家位置**任何一帧都不得落入任何 AABB 内部**（v3.0 §4.7 的十条已覆盖一部分，但**必须补上"旋转楼"的用例**）。
3. **运行时可视化**：HUD 上「碰撞」开关 → 画玩家周围 3 格内所有 AABB 的线框（红色=挡住的轴，绿色=可通行），并打印被挡住的箱子 id。**这是"我再也不信穿墙"的唯一可靠手段。**

### 2.4 验收

1. `audit-city.mjs` 的悬空清单、陷地清单、AABB 覆盖不匹配率三条全过。
2. 真机：沿所有街道贴墙走 10 分钟，穿墙 0 次；楼、车、路灯、花圃的底部与地面**看不出缝**。
3. 打开碰撞线框：**每一个看得见的实体都有对应的红框**（这条现在必然失败，是本轮必修项）。

## §3 建模精致度（手机要精致，PC 要极致）

> 原则：**精致 ≠ 面数多**，而是"层次 + 重复中的变化 + 材质 + 光影 + 贴地"。
> 但你要"极致"，那就必须**把细节写成清单**，一档一档加上去，并且每档都有面数预算。

|---|---|---|---|---|---|---|

## §4 地面黄黑条纹（atlas 格位错位）

### 4.1 现象与根因

现象：路面出现工地围挡那种**黄黑斜条纹**。
根因（按概率排序，实施时逐条排除）：

1. **UV 矩形取错格**：地面 quad 用了 `getAtlasRect(11)`（围挡）或格位索引与图集绘制顺序对不上（画的时候按 A 顺序，取的时候按 B 顺序）。
2. **V 轴翻转**：`DynamicTexture` 默认 `invertY = true`，而手写的 UV 没有跟着翻 → 取到**上下相邻**的格（围挡常常紧挨着地面格）。
3. **mipmap 渗色**：ATLAS 各格之间没有留内边距（padding），远处的 mip 把小格混到一起 → 出现"条纹渗到地面"的观感。
4. **平铺比例失控**：沥青格的 `uScale/vScale` 被算成很小/很大 → 虚线被拉伸成条纹。

### 4.2 改法

| 措施 | 规格 |
|---|---|
| 单一权威格位表 | `ATLAS_RECT = { asphalt: 4, laneLine: 5, sidewalk: 6, grass: 7, metal: 8, glassDoor: 9, signA: 10, hoarding: 11, roof: 12, zebra: 13, wire: 14, blob: 15, winOffice: 0, winApartment: 1, winOld: 2, curtainWall: 3 }` —— **画与取都只引用这张表**，禁止裸数字 |
| 内边距 | 每格四周留 **4 px** padding（1024 图集 / 4×4 格时，每格画到 248×248，居中） |
| UV 收敛 | 平铺类（沥青/砖/草地）用 `WRAP` + 整数倍平铺；贴花类（斑马线/井盖/招牌）用 `CLAMP` |
| V 轴 | 统一约定在 `buildAtlas()` 里处理一次（要么 `invertY=false` 要么 UV 翻），**不许两处各翻一次** |
| 平铺比例 | 沥青：1 格 = 8 单位；人行道砖：1 格 = 2 单位；草地：1 格 = 6 单位。全部写成 `Q.tileScale` |

### 4.3 验收（必须看得见）

1. 输出 `tools/dump-atlas.mjs` → 把 atlas 存成 PNG，并把 16 格标号画在旁边；人眼确认"哪格是什么"。
2. 场景里放一排"贴图样片墙"（调试模式）：16 个立方体每面贴一格，站在前面逐格核对——**这是唯一能一次抓出格位错的方法**。
3. 运行时审计：遍历所有几何的 UV 范围，统计"每格被哪些物件使用"，输出表格；`asphalt/sidewalk` 格只允许被地面类使用。
4. 站街上截图：路面**不得出现任何黄黑斜条纹**（黄黑只允许出现在工地围挡上）。

## §5 巨人的视觉行为（永远知道你在哪 + 低头 + 眼球 + 不神经质）

### 5.1 感知模型：改成"全知"（这一条直接推翻 v3.0 的视线锥判定）

| 项 | v3.0（现在） | v4.0（改成） |
|---|---|---|
| 她知不知道你在哪 | 视锥 35° + 距离 800PH + 遮挡 → 常常不知道 | **永远知道**（`knowsPlayer = true` 恒定） |
| 影不影响追踪 | 影响 | **不影响**：无论你多远、藏多深、蹲多久，她都会向你走来并踩 |
| 视线锥还有用吗 | 判定用 | **只用于表演**（决定她此刻"看哪里/低不低头"），不参与追踪 |
| 听觉 | 用来触发发现 | 保留，只影响表演（转头看声源方向） |

**实现口径**：`update()` 里删掉 `canSee` 作为状态转移条件；`knowsPlayer` 恒 true；
状态机改成 **`approach → stompNear → stomp → recover → 重新锁定你 → approach`** 的无限循环。
"隐蔽"只影响**她的表演节奏**（先左右张望找人再低头看你），不影响"她会不会来"。

### 5.2 走向你 + 低头看你（姿态叠加）

- **朝向**：`root.rotation.y` 朝你插值，角速度上限 **20°/s**（比 v3.0 的 35°/s 慢，显得重）。
- **低头**：在 MMD 更新之后对头颈骨做**姿态叠加**（不动模型，不做缩放）：

| 距离（PH） | 首 X | 頭 X | 上半身 X |
|---|---|---|---|
| > 800 | 0° | 0° | 0° |
| 800 ~ 400 | +3° | +5° | +1° |
| 400 ~ 200 | +8° | +14° | +3° |
| < 200（踩踏前） | +12° | +22° | +6° |

叠加实现要点：
1. 用**四元数叠加**（`bone.rotationQuaternion` 左乘增量），不要直接赋欧拉角——会被动画覆盖或抖动。
2. 每帧的叠加值是**相对值**，先取动画本帧姿态、再加上增量、再写回；下一帧 MMD 会重算，不会累积。
3. **头颈之外还要有"身体语言"**：接近时肩膀微沉、抬手（用上臂骨小角度叠加）——只看头会很僵硬。
4. 叠加角度做**平滑**（0.25 s 插值），突然抬头/低头会像机械。

### 5.3 眼球转动（不要只转头）

- MMD 标准模型有 **`左目` / `右目`** 骨（部分模型没有，也有用 `両目`）；找不到时降级为**只转头**并在日志里写明。
- 眼球叠加：`±15°`（水平）/ `±10°`（垂直），跟随你与她的相对位置；和头部叠加**相加**，所以看起来是"头转大半、眼睛补一点"。
- 眨眼：用表情 morph（`まばたき`）周期 3~5 秒一次，每次 0.1 s 闭合。
- 没有眼骨但有 `両目` 的模型：直接转 `両目`。

### 5.4 视线调度（"不能一直锁定"怎么写）

`gaze` 子状态机，与身体状态并行：

| 身体状态 | 视线分配（秒） |
|---|---|
| `approach`（走向你） | 45% 看你 · 20% 看前方路面 · 20% 扫视街边（随机方位）· 15% 看她自己的脚下 |
| `stompNear`（抬脚前 0.8 s） | **100% 锁定你**（这是"她盯上你了"的表演） |
| `stomp`（落下） | 100% 看你脚下 |
| `recover` | 先抬头看别处 1 s，再重新锁定你 |
| `idle`（还没开始走） | 30% 看你 · 70% 四处张望 |

- 换目标时**视线先动、头再跟**（眼球 0.15 s 内到位，头 0.4 s 到位）——这是"像活人"的关键细节。
- 每次转头都要有**最小间隔**（≥ 1.2 s），否则会像摇头娃娃。

### 5.5 表情

| 触发 | morph | 强度 |
|---|---|---|
| 常态 | `まばたき` | 周期眨眼 |
| 发现你（每次重新锁定） | `にこり` 或 `笑い` | 0.35 脉冲 0.6 s |
| 抬脚前 | `怒り` 或 `口角下げ` | 0.5 脉冲 0.8 s |
| 踩空/被你躲开 | `困る` / `怒り`（小） | 0.3 |
| 踩中 | `笑い`（大） | 0.6 脉冲 1 s |

实现：**表情走独立的 morph 通道**，与骨骼同一时间轴（避免 timeline 打架）；找不到对应 morph 名时静默跳过（不同模型命名差异极大，必须容错）。

### 5.6 验收

1. 站在任何位置（含楼后、蹲在花坛后）→ **3 秒内**她开始向你移动（这条现在是失败的，必修）。
2. 她接近到 400 PH 内截图：**头是低下来的**（颈部骨骼世界朝向与水平面夹角 > 8°）。
3. 记录 10 秒：她看你的时间占比在 `approach` 状态下 **< 60%**（证明没有一直锁定）。
4. 眼骨转动可见（放大截图或骨骼角度日志：`左目/右目` 的角度变化 > 3°）。

## §6 巨人 vs 楼房（不穿模、不卡住、也不做塌楼）

### 6.1 矛盾与解法

你要的三件事互相打架：**不做塌楼**（省性能）＋ **腿不许穿楼**（不能穿模）＋ **不许被楼卡住**（不能卡死）。
唯一同时满足三者的解法是：**让该让路的楼在她落脚前"消失"**，而不是让她去撞楼。

### 6.2 主方案：落脚区预清空（推荐 A + C）

| 步骤 | 规格 |
|---|---|
| **A. 路径预判** | 每 0.5 s 预测她接下来 3 步的落脚窗口（用当前 `approach` 方向 × 步长 8.8 单位 × 脚宽 1.2 单位） |
| **B. 提前让路** | 窗口内的楼房：在她落脚前 **0.8 s** 开始"下沉 + 压扁"（Y 缩到 5%，200 ms），然后隐藏；**只隐藏网格，AABB 一并移除**（玩家可跑进废墟） |
| **C. 卡住自救（必须做）** | 监控她的水平位移：若 **1.5 s 内位移 < 0.3 单位且不在踩踏动作中** → 立刻清除她前方 1.5 单位半径内的所有楼（网格 + AABB），并触发一次"踏步"动作解除 |
| **D. 视觉遮丑** | 楼"消失"的时刻用一次灰尘 + 碎片薄片掩盖（0.4 s），玩家看到的是"楼被踩没了"，而不是"楼凭空消失" |
| **L2/L3 可选** | 楼被踩时切成 6~10 块碎片飞散（PC 档才开），手机档保持"压扁消失" |

### 6.3 明确不做

- ❌ 真正的刚体/碎块物理（性能与稳定性都不可控）
- ❌ 她与楼的硬碰撞（一定会卡住，见 C 兜底）
- ❌ 楼倒塌的连续动画（手机上性价比为负）

### 6.4 验收

1. 连续观察 3 分钟：她的腿与任何楼网格的**交叠帧数 = 0**（用离线审计：逐帧检查腿的 AABB 与楼 AABB 是否相交）。
2. 连续观察 3 分钟：她**原地不动超过 1.5 秒的次数 = 0**（自救项必须真的触发过至少一次）。
3. 玩家跑到"废墟"上：能站、能跑，不再被隐形墙挡住。

## §7 物理稳定（长裙乱飘、抽搐）

### 7.1 根因（按影响排序）

| # | 根因 | 现象 | 改法 |
|---|---|---|---|
| 1 | **时间步不稳**：裸用 `dt` 直推物理，掉帧时 dt 抖动 → 弹簧爆炸 | 抽搐、乱飘、衣服"炸开" | **固定步长累积器**：物理固定 1/60 s（PC 可 1/120），单帧最多补 3 步，剩余时间丢弃 |
| 2 | 子步不足（默认 3） | 长裙薄片互穿、抖动 | 手机 **4**、PC **6~8**（`setPhysics({substeps})`） |
| 3 | 物理与动画更新顺序错 | 衣服比身体慢半拍、抖动 | 物理紧随 MMD 的 `beforePhysics` 阶段；渲染读"插值后"的骨骼 |
| 4 | 缩放模型（历史坑） | 弹簧参数脱离标定区间 → 乱飞 | **严禁缩放**（全球铁律） |
| 5 | 模型自带刚体参数不适合剧烈动作 | 长裙自穿、抽动 | 每模型一份 `physics.json` 覆盖：阻尼 / 重力 / 质量 / 迭代数（见 7.2） |
| 6 | 无速度上限 | 单帧位移巨大 → 视觉抽搐 | 给物理骨骼加**最大角速度/线速度限幅**（钩子在 `afterPhysics` 后做修正） |
| 7 | 掉帧时动画倍率跳变 | 动作一顿一顿 | 时间轴用固定步长推进（与 #1 同一处修） |

### 7.2 每模型物理标定（这条是"长衣服不抽搐"的实战关键）

```json
// assets/physics/<模型名>.json （可选，缺省用全局默认）
{ "substeps": 4, "gravity": 9.8, "damping": 0.25, "maxLinearVel": 8, "maxAngularVel": 6, "iterations": 8 }
```
- 上架流程：加载模型 → 在游戏模式跑 10 秒走路 → 自动采样裙摆骨骼的**相邻帧速度**：
  中位数 `m` 与 99 分位 `p`；若 `p > 3m` → 判定"抽搐"，自动提高 `damping` / 提高 `iterations` 重测（最多 3 轮）。
- 严重超长（礼服/拖地长裙）→ 启用**"半物理"档**：只保留贴身的 2~3 条物理链，外面几层用"跟随骨骼 + 阻尼平滑"（伪布料）。这一条比任何参数都有效。

### 7.3 验收

1. 录 60 秒走路：裙摆骨骼相邻帧速度的 `p99 / median < 3`（无尖峰）。
2. 掉帧注入测试（人为把帧率压到 20 fps 再恢复）：物理不炸、不抽搐。
3. 换 3 个不同模型（含一个长裙、一个长发）各跑一遍，全部通过。

### 8.2 新规则：每个街区必须有内容

| 水岸 | ≥ 35% | 河 + 桥 + 护栏 + 泊船 + 步道 + 亲水平台 |

**空地比例上限**：全城"完全无内容"的路面/空地 ≤ **15%**（广场/公园/水面不计入）。

## §13 实施顺序（一次做完，按依赖排列）

**第一组 · 地基修错（必须先做，后面都依赖它）**

5. `quality.js` 四档 + 所有细节函数吃 `Q`（§3.1）。

9. 城市密度规则 + 街区内容表 + 空地热力图（§8）。

**第三组 · 巨人**
10. 感知改全知 + 状态机循环（§5.1）。
11. 头颈姿态叠加 + 平滑（§5.2）。

## §14 风险与边界（提前说清楚）

| 风险 | 说明 |
|---|---|
| "极致细节"与手机性能天然冲突 | 所以必须**分档**；手机档给"看得出的精致"，PC 档给"数得清的细节"。同一份代码，靠 `Q` 切换。 |
| 全知追踪可能显得"作弊" | 用**表演层**补回来：她会先张望、再锁定、再走过去；被发现感靠表情与低头，而不是靠"看不见你"。 |
| 预清空楼房可能被她走一路推平半座城 | 加限制：每次只清 1 个街区、且只有落脚窗口内的；被清过的街区在 HUD 上计"破坏数"（顺便是成就感）。 |
| 眼骨/表情 morph 各模型命名不一 | 全部走**容错查找 + 静默降级**，找不到就只做头部与姿态。 |
| 物理标定不能一次到位 | 做成"自动采样 → 判定 → 调参重测"的闭环（§7.2），不靠人工试。 |
